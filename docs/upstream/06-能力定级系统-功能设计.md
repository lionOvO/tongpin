# 功能设计：能力定级系统（Tier-Based Assessment）（v2.3）

> 编制：司南｜2026-10-08｜v2.0 重写：2026-10-09｜**v2.1 修订：2026-10-10｜v2.3 修订（呈现纪律）：2026-10-10**｜归属项目：人才发掘 Agent 项目
> 定位：人才发掘流程中 **Evaluation Agent 的定级子能力**（docs/05 §2.2），插入 Matching → 人工闸门之间
> **在系统中的角色（v2.2 明确）**：本系统是**支撑件**——它生产的是核心功能（双边偏好匹配 PM 层）所依赖的**"能力尺"**。PM 层的匹配档位要成立，前提是**两侧共用同一把能力量规**；本系统是这把尺的**生产地与唯一版本源**（企业侧定档 EV-001 + 求职者侧量规差距说明 TM-003 同源引用）。**若两侧各有一套定级口径，"双边同尺"即失效。**
> 原则：**量规锚定定档（非 LLM 自由判断）+ 证据强制引用 + 维度优先级可配 + 缺证据不定档**
>
> ⚠️ **v2.0 范式收口说明**：本文档成稿于"综合评分"范式，v1.1 曾以"综合分降级为排序参考"过渡；**v2.0 起彻底移除评分体系**——不再产出综合分、不再使用 0-100 分数与百分比权重。以下内容已按 **PRD v2.1（EV-001~011）** 全文重写；配置资产以 `docs/07` 为权威版本，能力画像与熟练度设计以 `docs/recruit/08` 为权威版本。
>
> ⚠️ **v2.1 变更摘要**：①**新增 §3.4 需求—评估对齐校验（RQ-004 联动）**——本系统不再只对"简历"负责，同时对**需求侧**负责：定级前须校验 P0 需求有无量规覆盖，无覆盖的需求不得参与定级（**不允许 Agent 自由发挥去评**）；②新增 §3.5"需求来源标签 → 维度优先级"的前置规则（**无来源标签的要求不得设为 P0**）；③§7 公平性机制第 1 条补"量规须可被需求侧追溯"；④§11 新增两条风险（需求侧标准悬空、量规与需求版本错配）；⑤§12 排期补阶段 2 的 RQ-004 联动工作量。
>
> ⚠️ **v2.2 位置说明（不改变本文件功能内容）**：本系统作为**支撑件**，其"两侧同尺"的职责在核心功能（PM 层）的排期中具有**前置于匹配**的地位——**M1 交付顺序中，EV 层必须先于 PM 层可用**。同时，M1 并入 **RQ-001** 后，本系统在 M1 即需处理"企业侧用 JD 画像 or 用人需求画像"的输入选择（JD 为对外广告、Brief 为对内规格），§3.4 的完整校验（RQ-004）仍属阶段 2。
>
> ⚠️ **v2.3 呈现纪律说明（不改变定级算法，只改"结论怎么被人看见"）**：本系统产出的**档位本身不变**，但**对外的措辞按端区分**（PRD §6.3 第 7 条、红线 14）：①**企业端不出现"档位/评级/B1~B5"字样**，一律输出"**与岗位要求的差距**"（高于要求 / 相符 / 低于要求 {n} 级）；②**求职者端保留档位**（用于看"距离"），但每处档位必须与具体岗位要求同屏；③**报告首屏与页脚须默认可见 AI 偏差提示**（含"可能存在偏差"与"不设合格线"两要素）；④**全站零阈值语义**。**理由**：本系统是"标尺的生产地"，而**标尺的刻度是由本系统测定的，所以本系统有责任阻止它被当成判决书**。**实现要点**：两端渲染必须基于**同一份定级/匹配结果记录**，仅在渲染层做措辞映射——**严禁为企业端单写一套口径**。

## 1. 需求概述

| 项 | 内容 |
|----|------|
| 功能名 | 能力定级系统（Tier-Based Assessment） |
| 一句话 | 对单份简历按可配置维度量规**定档**（B1~B5，跨档输出档位区间），输出**能力结构视图 + 档位明细 + 待验证清单**，支撑人工作出判断 |
| 用户 | HR/面试官（报告消费方）、系统（定级执行方=Evaluation Agent） |
| 成功标准 | 同一简历重复定级 3 次**各维档位一致率 ≥90%** 且不跨越 B3/B4 边界；每个档位均可追溯到简历证据；证据不足维度明确标记而**不入档、不降档**；**报告内不出现任何总分** |
| **v2.1 补充成功标准** | **定级前完成 RQ-004 对齐校验**：所有 P0 需求与不可妥协项均有量规覆盖，否则该需求**不参与定级**并在报告标注"该需求不可评估"（不漏报、不硬评） |

## 2. 定级框架设计

### 2.1 定级维度（核心 3 维 + 推荐扩展 2 维）

| 维度编号 | 名称 | 评估对象 | 定档依据来源 | 优先级（校招技术岗） |
|---------|------|---------|-------------|-------------------|
| D1 | 专业匹配度 | 候选人专业 ↔ 公司业务领域 | **专业-领域映射配置表**（维护专业名到业务领域的映射及匹配档位；不让 LLM 自由判断专业相关性） | P1 重要 |
| D2 | 学业成绩表现 | GPA / 排名 / 奖学金 | 简历原文数据 + 百分位落档表（§2.3） | P2 参考 |
| D3 | 项目经验对口程度 | 个人/课程/实习项目 ↔ 岗位方向 | 项目描述逐条比对岗位画像 + 成果量化程度 | **P0 核心** |
| D4（扩展） | 技能匹配度 | 技能清单 ↔ 岗位硬性/加分要求 | 技能熟练度证据定级（L1~L4）+ 岗位要求等级比对 | P1 重要 |
| D5（扩展） | 实践/实习相关度 | 实习单位与岗位 ↔ 公司业务 | 实习相关性 + 职责深度 | P2 参考 |

> D1-D3 为必选维度；D4/D5 为建议扩展（完整画像需要，且防止"只看项目"的单一偏差），支持按岗位开关。默认模板启用全部 5 维；关闭维度后，**排序键仅按启用维度生成**（不再有"权重归一"问题）。

### 2.2 档位锚点（每维 B1~B5，纯序数，不含分数）

统一档位语义（全维度共用）：**B5 显著超出 / B4 达标 / B3 略欠（差 1 级）/ B2 明显不足（差 2 级）/ B1 不具备（差 ≥3 级）/ `insufficient` 证据不足（不入档）**。

以 D3 为例（其余维度同结构，全文见 `docs/07 §A`）：

| 档位 | 锚点描述（满足全部特征方可入档） | 证据要求 |
|------|--------------------------------|---------|
| B5 | ≥2 个项目方向与岗位核心方向直接对口，且担任核心角色，有量化成果 | 每个判断点附简历原文片段 |
| B4 | 1-2 个项目方向直接对口，角色较核心，成果可描述 | 同上 |
| B3 | 项目方向部分相关（相邻领域），或方向对口但角色边缘 | 同上 |
| B2 | 仅课程/练手项目相关，无实质成果 | 同上 |
| B1 | 无相关项目经验（整体信息完整前提下的"无"） | 判定说明 |

**定级纪律**：Agent 必须按锚点判定**命中的档位**；**不设档内取分、不设 ±微调**；引用的证据片段必须直接支撑锚点特征，**无证据支撑的特征不得计入**。当证据同时部分满足相邻两档特征 → 输出**档位区间**（如 B3–B4）并写明跨档依据，**不得取中间值**。

### 2.3 成绩标准化与 D2 定档（防分制混乱）

| 原始数据形式 | 处理规则 |
|-------------|-----------|
| 百分制 GPA（如 3.5/4.0） | 换算为百分位 = GPA ÷ 满分 × 100，按百分位落档（详见 `docs/07 §A.2`） |
| 排名（如 5/120） | 百分位 = (1 - 排名/总人数) × 100；排名优于 GPA，优先采用 |
| 奖学金/荣誉 | 作为**档位上调**依据（最多上调 1 档），不单独成档 |
| 无成绩信息 | 不猜测 → `insufficient`（§4 缺证据处理） |

## 3. 维度优先级配置（替代原"权重配置"）

- 维度重要性以**优先级序数**表达：**P0 核心 / P1 重要 / P2 参考**（JSON，热更新）。**不设百分比权重，不做 Σ=100% 校验。**
- 优先级只用于两处：①**排序键中维度的比较次序**（EV-005）；②报告与结构摘要的呈现顺序与强调。**不参与任何算术运算。**
- 内置预设模板（详见 `docs/07 §C`）：校招技术岗（D3=P0；D1/D4=P1；D2/D5=P2）、校招非技术岗（D1/D3=P0；D2/D5=P1；D4=P2）、社招通用（D3/D5=P0；D1/D4=P1；D2=P2）。
- **配置校验**：至少 1 个 P0 维度；同一维度不得重复配置优先级；启用维度须全部有优先级。校验失败拒绝保存。

> 为什么不用百分比权重：权重只有在"合成一个总分"时才有意义；定级范式下不合成标量，权重就退化为**装饰性数字**。改用优先级，既表达了"哪项更重要"，又不制造 45% 对 40% 的伪精确差值。

### 3.4 需求—评估对齐校验（RQ-004 联动，v2.1 新增）

> **为什么本系统要管需求侧**：定级的上限由需求定义——**需求错了，后面做得再严谨也只是把错误执行得更精确**。v2.1 在定级链路前插入一道校验，使"标准侧"也受约束。

**校验流程（定级前置步骤）**：

```
输入：用人需求画像 hiring_briefs（RQ-001/RQ-002 产物）
  │
  ▼
逐条需求校验「需求 → 维度 → 量规条目 → 证据要求」四要素是否齐全：
  ├─ 齐备 → 该需求可评估，参与定级
  └─ 缺失 → 标「该需求当前不可评估」→ 进待处理清单 → **不生成该需求的任何档位结论**
  │
  ▼
输出：对齐校验结果（供报告与 HR 可见）
```

| 需求类型 | 校验要求 | 缺失时行为 |
|---------|---------|-----------|
| **不可妥协项**（硬门槛） | 必须有对应维度 + 量规档位锚点 + 证据要求 | 标"不可评估"，**不强行给档**，进待处理清单 |
| **P0 优先级需求** | 同上 | 同上 |
| P1/P2 需求 | 尽量映射 | 未映射仅记录，不阻塞定级 |
| `未澄清` 需求 | **不参与校验与定级** | 报告中显式标注"需求未澄清"，**不代填、不猜测** |

**硬约束**：

- ❌ **不允许 Agent 自由发挥去评**——无量规覆盖的需求，Agent **不得**自行设计评价标准；
- ✅ 校验结果必须**同时可见于报告与需求侧**（同一结论、两个方向，与 RQ-003 诊断的双端投影同构）；
- ✅ 校验留痕（进 `audit_logs`，`event_type = 需求对齐校验`）。

### 3.5 需求来源标签 → 维度优先级的前置规则（v2.1 新增）

> 与 §3.4 配套：**没被溯源的需求，不该拥有最高优先级**。

| 规则 | 内容 |
|------|------|
| 前置条件 | 一条需求只有在 **RQ-002 溯源**完成（带来源标签）后，**才允许被设为 P0 优先级** |
| 无标签时 | 该需求**可保留在画像中**，但**无法被设为 P0**，界面给出说明（"该要求未标注来源，不能作为核心门槛"） |
| 模板惯性 | 标签为 `模板惯性` 的需求**必须经过 HR 确认**才能进入优先级配置，且**默认建议降级** |
| 与量规的关系 | 优先级只影响**排序键次序与呈现顺序**（§3 原规则不变）；本规则约束的是"**能不能被设为 P0**"，不改变优先级的语义 |

**验收**：Given 某岗位 6 条要求中 1 条未标注来源，When 配置优先级，Then 该条不能被设为 P0 且界面提示原因；Given 一条来源为 `模板惯性`，When 设为 P0，Then 要求 HR 显式确认后才生效。

## 4. 档位汇总与缺证据处理

```
排序键（字典序，确定性代码生成，不产出任何总分）：
  ① 达标维度数（档位 ≥B4 的维度数，降序）
  ② 按维度优先级逐维比较档位序数（降序）：先 P0，再 P1，同级内按维度序号
  ③ 证据充分维度数（降序）
```

**缺证据处理（关键设计）**：

- 某维度证据不足（如简历无 GPA、无项目描述）→ 该维度标记 `insufficient`，**不入任何档位、不虚构分数、不按最低档计**；
- **该维度不参与排序键比较**（排序时跳过，并在报告"排序依据说明区"记录"因证据不足未参与比较"）；
- 该维度在报告的**证据不足区**显式列出，并自动生成待验证条目（EV-010）；
- **原 redistribute / zero 两种"权重模式"已取消**——它们是分数合成体系的产物，定级范式下不存在权重重分配问题。

**置信度分级**（复用项目统一机制）：

- 高置信：全部维度有证据且引用完整 → 报告直接可用；
- 低置信：≥2 个维度证据不足，或 Agent 自评存在无法引用支撑的推断 → 报告标注"低置信，建议人工复核"并进入人工队列。

## 5. 定级流程（Agent 执行）

```
输入：简历文本 + 岗位模板(维度/维度优先级/量规) + 岗位画像(JD解析产物) + **用人需求画像(阶段 2)**
  │
  ▼
【阶段 2 新增】需求—评估对齐校验（RQ-004，§3.4）：P0 与不可妥协项须有四要素覆盖，
  无覆盖 → 标"不可评估"、进待处理清单、不参与定级
  │
  ▼
Evaluation Agent（定级模式）：
  1. 逐维度：检索证据片段（简历原文定位）→ 按量规判定命中档位（跨档则输出区间）→ 生成定级理由(引用证据)
  2. 技能项：熟练度证据定级 L1~L4 → 与岗位要求等级 R 比对 → 技能达标档位
  3. 缺证据维度打 insufficient 标记，不入档、不输出猜测档位
  4. 生成结构视图三区块 + 结构摘要句 + 待验证清单
  5. 结构化输出（Pydantic schema 强校验，校验失败整体重试 1 次，再失败转人工）
  │
  ▼
计算层（确定性代码，非 LLM）：档位汇总 → 排序键生成 → 报告组装
  │
  ▼
人工闸门：HR 审阅报告 → 确认 / 修改单维档位(留痕) / 打回重定级
  │
  ▼
结果入库 + 修改记录回流记忆（校准后续定级）
```

> 设计要点：**LLM 只做"按量规定档 + 找证据 + 生成理由"，不参与任何算术**——排序键由确定性键比较得出，杜绝 LLM 算错加权或臆造总分（EV-005）。**阶段 2 起，本链路前面多了一道对"需求"的校验（RQ-004）**：不只问"这个人行不行"，先问"这条要求本身能不能评"。

**注意**：对象中**不存在 composite_score / 任何分数 / 任何百分比权重字段**（v2.0 硬约束）。

报告页展示顺序：**能力结构视图（首屏）→ 技能熟练度矩阵 → 档位阶梯图 → 维度档位明细 → 面试准备区（待验证清单 + 追问清单）→ 排序依据说明区 → 人工操作区**。

**报告页脚**固定一句使用说明（轻口径，不做视觉强调、不进首屏）：**「本报告依据简历文本整理，结论供招聘决策参考，请结合面试与实际沟通综合判断。」** 全文**不得出现"未经核验""真实性"等字眼**；**"验证/追问"类提示只允许出现在面试准备区与页脚两处**——首屏结构视图、档位表、排序页一律不出现，也不在候选人之间对证据可核验性作差异化呈现（见 PRD §6.3 结论表述纪律）。

## 7. 客观性与公平性保障（6 项机制）

| # | 机制 | 说明 |
|---|------|------|
| 1 | 量规锚定 | 五档行为描述定档，杜绝自由判断；量规随版本管理；**v2.1 补充：量规条目须可被需求侧（`hiring_briefs` 的 P0 需求）追溯，否则该需求不得进入定级**（RQ-004） |
| 2 | 证据强制引用 | 无证据不定档（复用全项目引用纪律） |
| 3 | **定级一致性验收** | 同一简历重复定级 3 次，**各维档位一致率 ≥90% 且不跨越 B3/B4 达标边界**，纳入评测脚本 |
| 4 | 校准集 | 用标注集抽 20 对做校准：**Agent 档位与人工标注档位一致率 ≥80%、跨 ≥2 档严重偏差 ≤10%** 后冻结量规 v1 |
| 5 | 偏见审计联动 | Audit Agent 对照简历对测试：仅改敏感属性（性别/年龄等）后**任一维度档位差 ≥1 档即告警**；**院校层次不作为任何维度加分项**（防学历歧视） |
| 6 | **结论表述纪律** | 系统定位为"**证据整理者而非能力认定者**"：禁用能力断言词（具备/掌握/精通/确实/证实），统一用"简历显示/简历描述/简历自评"；档位表示"**简历证据所支持的水平**"，不得表述为对个人能力的认定；**验证类提示仅限面试准备区与页脚**，不在主视觉与人才端出现（见 PRD §6.3） |

## 8. 配置项汇总

| 配置 | 默认 | 说明 |
|------|------|------|
| dimension_priorities | 见 §3 模板 | 维度优先级（P0/P1/P2），只影响排序键次序与呈现顺序 |
| dimensions_enabled | 全 5 维 | 按岗位模板开关；关闭后排序键仅按启用维度生成 |
| assess_repeat_times | 3 | 一致性验收重复次数 |
| pass_threshold | **不存在该配置** | 系统不设"自动通过线"，也**不产出可用来设线位的总分**——排序仅辅助人决策 |

## 9. 异常与边界场景

| 场景 | 触发 | 系统行为 |
|------|------|---------|
| 证据不足 | 维度无支撑数据 | `insufficient` 标记 + **不入档** + 不参与排序键比较 + 报告证据不足区列出 |
| 证据跨档 | 证据部分满足相邻两档 | 输出**档位区间**（如 B3–B4）+ 跨档依据；**不取中间值** |
| GPA 分制不明 | 仅写"GPA 3.5"无满分 | 按常见满分(4.0/5.0)双算取**保守档位**并标注"换算待确认" |
| 简历信息冲突 | 两处成绩不一致 | 采信较新/更正式一处，另一处在报告中并列展示并标注 |
| 量规不适配 | 岗位类型无对应预设 | 强制先创建/复制模板，禁止用默认模板裸跑 |
| Agent 输出校验失败 | schema 不通过 | 重试 1 次 → 转人工定级队列（不留半成品档位） |
| **P0 需求无量规覆盖**（v2.1 新增） | RQ-004 对齐校验发现覆盖缺口 | 标"该需求当前不可评估"、进待处理清单、**不生成任何档位结论**（**不允许 Agent 自由发挥去评**） |
| **需求未澄清**（v2.1 新增） | 澄清问题被跳过 | 标 `未澄清`、**不进入 P0 优先级、不参与定级**；报告显式提示而不猜测内容 |

## 10. 验收标准（Given/When/Then）

1. 给定岗位模板（D3=P0，D1/D4=P1，D2/D5=P2）与一份含完整 GPA 和 2 个对口项目的简历，当执行定级，则输出各维度**档位**（不含分数）、每维附 ≥1 条简历原文证据，且报告内无任何总分。
2. 给定一份"方向对口但角色边缘"的项目经历，当定级 D3，则输出 **B3–B4 区间**并附跨档依据，而非取中间值。
3. 给定一份无 GPA 的简历，当执行定级，则 D2 标记 `insufficient`（**不入档、不按 B1 计**）、报告在证据不足区列出、排序依据中标注"D2 未参与比较"。
4. 给定同一简历连续定级 3 次，当比对结果，则**各维档位一致率 ≥90%**，且不出现跨越 B3/B4 边界的翻转。
5. 给定 HR 将 D3 档位由 B4 改为 B3 并填写理由，当提交，则报告更新、修改留痕（改前/改后/理由/操作者）并写入校准记忆。
6. 给定仅修改候选人敏感属性的对照简历对，当 Audit Agent 审计，则**任一维度档位差 ≥1 档**时产生告警记录。
7. **（v2.1 新增）** 给定一条"不可妥协项"未映射到任何评估维度（无量规覆盖），当执行定级，则报告标注"该需求不可评估"并留痕，且**不生成该需求的任何档位结论**（RQ-004）。
8. **（v2.1 新增）** 给定一条未标注来源的岗位要求，当配置维度优先级，则**该条无法被设为 P0** 且界面提示原因（§3.5）。

## 11. 风险与应对

| 风险 | 等级 | 应对 |
|------|------|------|
| LLM 量规执行漂移（定档松紧不一） | 中 | 校准集冻结量规 + 档位一致性验收 + AU-003 跨档率监控（>20% 告警） |
| 档位粒度变粗后区分度下降 | 中 | 判据表写得足够细（`docs/07 §A`）；跨档输出区间保留信息量；结构视图而非单一档位承担区分职责 |
| GPA 维度公平性争议（分制/院校差异） | 中 | 百分位落档 + 院校不加分 + 优先级默认最低（P2 参考级）+ README 声明该维度仅为参考信号 |
| 定级结果被误用为"一刀切门槛" | 低 | **系统不产出总分、不设任何阈值语义**；报告始终以结构视图 + 档位明细呈现，引导"看结构不看单一结论"；**v2.3 起进一步：企业端不出现"档位/评级"字样（红线 14）** |
| **需求侧标准悬空**（v2.1 新增） | **高** | RQ-004 对齐校验（§3.4）：P0 需求无量规覆盖 → 标"不可评估"、**不允许 Agent 自由发挥去评**；校验结果双端可见 |
| **量规与需求版本错配**（v2.1 新增） | 中 | 需求画像（`hiring_briefs.brief_version`）与量规（`rubric_version`）均版本化；定级记录同时写入两者版本；错配时拒绝定级并提示 |

## 12. 与路线图的关系（排期建议）

- 本功能为 **阶段 1（MVP）内的 Evaluation Agent 核心能力**，工作量估计 3-4 天（量规编写 1 天 + Agent 定级链路与 schema 1 天 + 报告页 1 天 + 一致性验收脚本 0.5 天 + 校准 0.5 天）。**v2.2 说明**：本系统在 M1 内**必须先于 PM 层可用**——它是 PM 层"能力尺"的供给方（见文件头"角色"段）。
