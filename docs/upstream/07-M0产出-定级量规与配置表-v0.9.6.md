## 通用定级纪律（对全部维度生效）

1. **只定档、不取分**：Agent 必须输出命中的档位标识（如 `B4`）；**不设档内取分、不设 ±微调**。若证据同时部分满足相邻两档的锚点特征 → 输出**档位区间**（如 `B3–B4`），并写明跨档依据。
2. **无证据不定档**：任一锚点特征若无简历原文支撑，不得计入该档；整体无证据 → `insufficient`（EV-004，**不入档、不按最低档计**）。
3. **等级不得拔高**：原文写"了解/熟悉/精通"必须按原文等级判定，Agent 不得推断为更高等级（MT-002 负向验收）。
4. **敏感属性禁用**：性别、年龄、民族、婚育、政治面貌、院校层次（985/211/双一流）不得作为任何档位判据（AU-001）。
5. **理由三要素**：每条维度理由 = 命中档位 + 锚点特征命中情况 + 证据引用；输出区间时另附跨档依据。
6. **区分"没有"与"未写"**：简历明确未提及某类经历且整体信息完整 → 按"无该类经历"落 **B1**；简历信息严重不完整（如仅半页）→ 按证据不足处理（`insufficient`）。此判定须在理由中说明。
7. **表述纪律（v0.9.5 新增）**：系统是**证据整理者，不是能力认定者**——维度理由、摘要句与清单条目一律用"简历显示 / 简历描述 / 简历自评"陈述证据，**禁用"具备 / 掌握 / 精通 / 确实 / 证实"等断言词**；档位表示"简历证据所支持的水平"，不得表述为对个人能力的认定。**"验证/追问"类提示仅允许出现在报告的面试准备区与页脚**，不得进入首屏结构视图、档位表、排序页与人才端（详见 PRD §6.3 结论表述纪律）。
8. **锚点可双向引用（v0.9.6 新增）**：每个档位的锚点描述**必须可被独立引用**——企业侧用于定档（EV-001），求职者侧用于量规差距说明（TM-003）。因此锚点描述须**自足**（不依赖上下文即可读懂"这一档要求什么"），且**不得内嵌分数、不得引用其他档位的表述**。

> **档位语义（全维度统一，序数等级，不映射分数）**：
> **B5 显著超出**（证据明显高于岗位要求，可作团队补强项）/ **B4 达标**（证据与要求相符）/ **B3 略欠**（差 1 级，通常可短期弥补）/ **B2 明显不足**（差 2 级）/ **B1 不具备**（差 ≥3 级，或经判定的事实性"无该类经历"）/ **`insufficient`**（证据不足，不入档）。

## A. 定级量规全文（Rubric v0.9）

### A.1 D1 专业匹配度

判据来源：**专业-领域映射配置表**（§B）。档位由候选专业 × 目标岗位所属领域查表得出；辅修/双学位/相关证书可作为档位上调依据（最高至 B5）。

| 档位 | 锚点描述（映射表档位） | 证据要求 |
|------|----------------------|---------|
| B5 | 直接对口专业 + （辅修/双学位/行业证书 满足其一） | 专业名称 + 辅修或证书原文 |
| B4 | 直接对口专业 | 专业名称原文 |
| B3 | 相邻相关专业（映射表标注"相邻"） | 专业名称原文 |
| B2 | 弱相关专业（映射表标注"弱相关"），或专业未填写但课程/技能线显示可迁移 | 专业或课程清单原文 |
| B1 | 无关专业且无迁移证据 | — |

### A.2 D2 学业成绩表现

判据来源：标准化百分位（EV-003）。**排名优先于 GPA**；奖学金/荣誉作为**档位上调**依据（最多上调 1 档），不单独成档。

| 档位 | 锚点描述 | 证据要求 |
|------|---------|---------|
| B5 | 百分位 ≥ 90（或排名前 10%），或国家级奖学金 | 成绩/排名原文 |
| B4 | 百分位 75-89（前 25%） | 同上 |
| B3 | 百分位 60-74（前 50%） | 同上 |
| B2 | 百分位 40-59（前 75%） | 同上 |
| B1 | 百分位 < 40（后 25%） | 同上 |

特殊处理：GPA 无满分信息 → 按 4.0/5.0 双算取**保守档位**并标注"换算待确认"；成绩与排名均无 → `insufficient`（**不得按最低档计**）。

### A.3 D3 项目经验对口程度（**优先级最高：P0 核心维度**，判据从严）

"对口"判定基准：项目方向命中岗位画像的"方向关键词集合"（由 JD-001 产出）；角色深度指主导/核心/参与；成果量化指有数字或可验证产出（上线、用户量、性能指标、开源 star 等）。

| 档位 | 锚点描述 | 证据要求 |
|------|---------|---------|
| B5 | ≥2 个对口项目 + 至少 1 个担任主导/核心角色 + 至少 1 项量化成果 | 每个判断点独立引用 |
| B4 | 1-2 个对口项目 + 核心/参与角色 + 成果可描述（无论文数字） | 同上 |
| B3 | 项目方向部分相关（相邻领域），或方向对口但角色边缘 | 同上 |
| B2 | 仅课程设计/练手项目相关，无实质成果 | 同上 |
| B1 | 无相关项目（整体信息完整前提下的"无"） | 判定说明 |

> B3 与 B4 之间常出现"方向对口 + 角色边缘"这类混合情形 → 按通用纪律第 1 条输出 **B3–B4 区间**，不取中间值。

### A.4 D4 技能匹配度（v0.9.3 重写：布尔命中 → 熟练度达标档位；v0.9.4 去分数化）

**判据变更**：不再以"会不会"计命中，改为**先给每项技能做证据锚定的熟练度定级（L1~L4）**，再与岗位要求等级比对得**达标档位**。

**第一步：熟练度定级（EV-011，以证据定级，不以自述定级）**

| 等级 | 名称 | 判定证据要求（须引用简历原文） |
|------|------|------------------------------|
| L4 | 精通 | 深度证据之一：架构设计 / 性能优化并量化 / 开源贡献 / 技术分享或教学 / 专利论文 |
| L3 | 熟练 | 可验证产出：功能上线、指标改善、作品链接、被他人使用 |
| L2 | 熟悉 | 有使用场景描述（课程/项目/实习中使用过，含任务与对象） |
| L1 | 了解 | 仅出现技能名，无任何使用场景 |
| L0 | 无证据 | 未提及或仅见于自我评价套话（→ `insufficient`，不入档） |

三条硬纪律：①自述等级 > 证据等级时按**证据等级**记录，并生成待验证条目（EV-010）；②不得跨级推断（"用过 Redis" ≠ "精通分布式缓存"）；③每个等级须附 ≥1 条原文引用，无引用不得定级。

**第二步：技能达标档位（岗位要求等级 R vs 候选人证据等级 L）**

| 关系 | 档位 | 含义 |
|------|------|------|
| L ≥ R+1 | **B5** | 显著超出要求（可作团队补强项） |
| L = R | **B4** | 正好达标 |
| L = R−1 | **B3** | 略欠，通常可短期上手弥补 |
| L = R−2 | **B2** | 明显不足 |
| L ≤ R−3 | **B1** | 不具备 |
| L = L0 | `insufficient` | 证据不足，不入档 |

**第三步：D4 维度档位** = 岗位**硬性要求技能**达标档位的**中位数**（偶数项取**靠低者**，保守取向）；若硬性要求技能中任一项为 `insufficient`，则 D4 输出**区间**（如 B2–B4）并标注"部分证据不足"。**加分技能档位仅在技能矩阵中并列展示，不参与 D4 档位判定。**

> 设计理由：旧口径"缺 1 项就掉一档"会把"要求精通、候选熟练"与"要求精通、候选没听说过"同等处理；新口径产出的是**可行动的差距**——差 1 级属短期可补，差 3 级才是"不具备"。
>
> 为什么不用加权平均：加权会把结构抹平（`docs/recruit/07` M2 机制）。定级范式下 D4 用**序数中位数**，保证结果仍是一个有意义的档位，且不引入伪精确数值。

### A.5 D5 实践/实习相关度

| 档位 | 锚点描述 | 证据要求 |
|------|---------|---------|
| B5 | 相关领域实习 ≥6 个月 + 承担核心职责 | 实习描述 + 时长 |
| B4 | 相关领域实习 3-6 个月 | 同上 |
| B3 | 相关实习 <3 个月，或时长够但职责边缘 | 同上 |
| B2 | 有实习但与岗位领域无关 | 同上 |
| B1 | 无任何实习经历（整体信息完整前提下的"无"，**按事实落入 B1，非证据不足**） | 判定说明 |

> D5 是"无经历"与"未填写"区分最关键的维度：校招场景中无实习是常见事实，若按证据不足剔除该维度反而失真，故单独设 **B1 作为事实档**；而信息不完整的简历仍走 `insufficient`（**不入档**，不按 B1 计）。

### A.6 "不可妥协项 → 维度"映射说明（v0.9.6 新增，承接 RQ-004）

> **为什么需要这一节**：量规是**评估侧**的资产，但 v2.1 引入了**需求侧**的审查（RQ 层）。当 HR 在用人需求画像中标注了"不可妥协项"，系统必须能回答：**这条要求由哪个维度、哪个档位锚点来评？** 若答不上来，这条要求就是"标准悬空"，**不允许 Agent 自由发挥去评**（RQ-004）。

**映射关系（评估维度 ↔ 需求类型）**：

| 需求侧表述示例 | 承载维度 | 判定锚点 | 是否可评 |
|---------------|---------|---------|---------|
| "必须本科及以上学历" | D1 专业匹配度（间接）/ 硬性规则（MT-003） | D1 档位 + 规则引擎硬门槛 | ✅ |
| "必须有对口项目经验" | D3 项目经验对口程度 | §A.3 B4 及以上锚点 | ✅ |
| "必须熟悉 Java/Spring" | D4 技能匹配度 | §A.4 达标档位 B4（L = R） | ✅ |
| "必须有相关实习经历" | D5 实践/实习相关度 | §A.5 B3 及以上锚点 | ✅ |
| "必须成绩前 25%" | D2 学业成绩表现 | §A.2 百分位 ≥75 | ✅ |
| "有责任心""抗压能力强""认同公司文化" | **无对应维度** | **无** | ❌ **不可评** → 应进入 RQ-003 的"不具备可评性"诊断，或在 RQ-001 澄清阶段改为可评表述 |

**映射表维护规则**：

1. 新增**评估维度**时，须同时声明它能承接哪些**需求类型**；无承载维度的常见需求（如"有责任心"）应登记为**已知不可评需求清单**，供 RQ-003 诊断直接命中；
2. 新增**需求**时（RQ-001 澄清阶段），系统须校验其能否映射到 `§A.1~A.5` 的某个档位锚点；不能则标注 `不可评`，**不进入 P0 优先级**（RQ-002 前置规则，见 §C.4）；
3. 映射关系变更须记变更记录，并同步校验**存量 Brief** 是否受影响（只提示，不自动改）。

**验收**：Given 一份 Brief 含"必须熟悉 Kafka"与"有责任心"两条，When 执行 RQ-004 校验，Then 前者映射到 D4 判定可评估、后者标注"不可评估"进待处理清单，且**系统不为后者生成任何档位结论**。

### A.7 量规锚点作为 TM-003 差距说明的引用源（v0.9.6 新增）

> **这是本文件在求职者侧的作用**：TM-003（证据缺口与量规差距说明）**不生成学习建议**，它做的事是——**把量规的两个档位锚点原文并列展示，让差异自己说话**。

**生成规则**：

```
输入：技能/维度的岗位要求等级 R、候选人证据等级 L（L < R）
  │
  ▼
从本文件读取 §A.4（技能）或 §A.1~A.5（维度）中 R 档与 L 档的锚点描述原文
  │
  ▼
输出：R 档锚点原文 + L 档锚点原文 + 一句**定义差异陈述**
      （例："该维度要求 L3（能独立设计并排障）；简历证据为 L2（能使用）。差异在于：锚点要求『独立设计』与『排障』类经历。"）
```

**硬边界（与 PRD 红线 7/11 一致）**：

- ❌ 不推荐课程、书籍、技术路线、学习顺序；
- ❌ 不生成任何可直接粘贴进简历的文案；
- ❌ 不做"你应该转行/应该学别的方向"类判断；
- ✅ **只回答"该档标准是什么、你缺哪类证据"**——依据是本文件的锚点原文，**可引用版本号（`rubric_version`）**，完全可复现。

**验收**：Given D4 要求 L3、证据 L2，When 生成说明，Then 输出引用本文件 §A.4 中 L3/L2 锚点原文的差异陈述，且**不包含任何课程/资源/文案内容**。

## C. 维度优先级模板（v0.9.4 替代原"权重模板"）

### C.1 三个内置模板

> **口径变更（v0.9.4）**：**不再使用百分比权重，不做 Σ=100% 校验**。维度重要性以**优先级序数**表达：**P0 核心 / P1 重要 / P2 参考**。优先级只决定两件事：①排序键中维度的比较次序（EV-005）；②报告与结构摘要中的呈现顺序与强调。**优先级不参与任何算术运算。**

| 维度 | 校招-技术岗（默认） | 校招-非技术岗 | 社招-通用 |
|------|-------------------|--------------|----------|
| D1 专业匹配度 | P1 重要 | **P0 核心** | P1 重要 |
| D2 学业成绩表现 | **P2 参考** | P1 重要 | **P2 参考** |
| D3 项目经验对口程度 | **P0 核心** | **P0 核心** | **P0 核心** |
| D4 技能匹配度 | P1 重要 | P2 参考 | P1 重要 |
| D5 实践/实习相关度 | P2 参考 | P1 重要 | **P0 核心** |

### C.2 模板设计说明

- **校招-技术岗（默认）**：D3 设为 **P0 核心**（技术岗位项目作品是最强信号）；**D2 设为 P2 参考级**——技术岗招聘现实中项目与技能重要性显著高于成绩，且成绩维度弱预测、争议大（PRD v1.3 假设 H2，M0 访谈验证后可上调）；D1/D4 为 P1（专业是门槛信号、技能是硬性要求来源）；D5 为 P2（校招普遍无实习）。
- **校招-非技术岗**：D1/D3 设为 **P0**（无代码作品可看，专业匹配与项目经历是主信号）；D2/D5 为 P1（成绩与实习相对更重要）；D4 为 P2。
- **社招-通用**：D2 降为 **P2 参考**（工作经历替代学业信号）；**D3 与 D5 均为 P0**（经历与职责为中心）；D1 降为 P1（专业相关性随经验衰减）。
- **优先级与排序键的关系（重要）**：优先级相同则按维度序号比较。同一优先级可含多个维度，**不要求唯一排序**——这是与百分比权重的关键差别：它承认"这两项同等重要"，而不是硬造一个 45% 对 40% 的伪精确差值。
- 模板可复制后自定义；保存时校验：**至少 1 个 P0 维度 / 同一维度不得重复配置优先级 / 启用维度须全部有优先级**（EV-002）。
- **禁止**：任何模板不得设"达标线自动通过""综合分录取线"字段（系统不产出总分，见 PRD §6.3）。

### C.3 模板变更流程

新增/修改模板 → 记录变更原因与影响面 → 变更记录留痕 → 新批次生效（存量报告不回溯）。

### C.4 优先级设置的前置规则：来源标签（v0.9.6 新增，承接 RQ-002）

> **核心规则一句话**：**没被溯源的需求，不该拥有最高优先级。**

| 规则 | 内容 |
|------|------|
| 前置条件 | 一条岗位要求只有在 **RQ-002 溯源**完成（标有来源标签：`团队能力缺口 / 业务需要 / 合规或硬性制度 / 模板惯性 / 未澄清`）后，**才允许被设为 P0 优先级** |
| 无标签时 | 该要求**可保留在画像中**，但**无法被设为 P0**；界面提示"该要求未标注来源，不能作为核心门槛" |
| `模板惯性` | **必须经 HR 显式确认**才可设为 P0，且**默认建议降级** |
| `未澄清` | **不得进入任何优先级配置**，报告中显式显示"需求未澄清" |
| 与量规的关系 | 本规则约束的是"**能否被设为 P0**"；优先级本身仍只决定**排序键次序与呈现顺序**（§C.1 原口径不变），**不参与算术** |

**为什么这条规则重要**：P0 决定排序键的第一比较层次，等价于"最重要的门槛"。如果一条随模板抄来的要求能直接成为 P0，那么"需求规格化"就白做了——**这条规则是 RQ 层与 EV 层咬合的地方**（对应 PRD 红线 13 与 RQ-004）。

**验收**：Given 某岗位 6 条要求中 1 条未标注来源，When 配置优先级，Then 该条不能被设为 P0 且界面提示原因；Given 一条来源为 `模板惯性`，When 设为 P0，Then 要求 HR 显式确认后才生效；Given 一条标 `未澄清`，Then 它不出现在优先级配置候选中。

### C.5 维度优先级与需求层的关系（v0.9.6 新增）

| 层 | 资产 | 作用 |
|---|------|------|
| 需求层 | 用人需求画像（`hiring_briefs`） | 说明"这个岗位真正要什么"（每条带来源标签与可评性） |
| 配置层 | **本文件 §C 优先级模板** | 说明"评估时哪些维度更重要"（P0/P1/P2） |
| 评估层 | 本文件 §A 量规 | 说明"每个维度各档什么标准"（B1~B5 锚点） |

**三者的咬合点**：需求侧的"不可妥协项"必须映射到某个维度（§A.6），该维度改由优先级模板承载（§C），最终由量规定档（§A）。**任一环节缺失 → 该需求不可评估**，系统不得硬评（RQ-004）。

## D. 标准包（Rubric Pack）结构规范（v0.9.2 新增，对应 PRD SYS-004）

**定位**：把"量规 + 维度优先级模板 + 专业-领域映射 + 校准记录"打成**可迁移的配置快照**——换岗位/换客户只导入 pack，不改代码。

**命名**：`{scope}-{pack_version}.pack.json`，如 `tech-campus-v1.2.pack.json`。

**结构**（关键设计：**内联完整内容而非引用路径**——pack 迁移到新环境时不能依赖本地文件版本）：

```json
{
  "pack_version": "v1.2",
  "name": "校招技术岗标准包",
  "scope": "tech-campus",
  "created_at": "2026-10-09T10:00",
  "rubric": { "rubric_version": "v0.9", "dimensions": ["D1~D5 五档档位锚点全文，内联"] },
  "priorities": { "template": "校招-技术岗", "values": { "D1": "P1", "D2": "P2", "D3": "P0", "D4": "P1", "D5": "P2" } },
  "major_map": { "version": "v1", "content": ["8 领域映射表全文，内联"] },
  "calibration": { "anchor_pairs": 20, "tier_agreement": 0.82, "severe_deviation": 0.05, "last_calibrated_at": "2026-10-20" },
  "notes": "D2 优先级设为 P2 参考级（假设 H2）"
}
```

**打包与导入规则**：

| 规则 | 内容 |
|------|------|
| 禁止内容 | pack **不得**含候选人数据、审计日志、API 密钥、报告内容（防数据泄漏） |
| 导入校验 | 结构完整性（字段齐全）+ **优先级配置完整性**（至少 1 个 P0 维度 / 同一维度不得重复配置 / 启用维度须全部有优先级）+ 版本字段非空；任一失败拒绝导入并提示具体原因 |
| 生效范围 | 导入后**新批次**生效；存量报告不回溯（与 EV-007 一致） |
| 版本留痕 | 导入后 job_profiles.pack_version 与 **ability_reports.pack_version** 记录来源，便于审计追溯 |

> **v0.9.6 补充**：pack 的 `priorities` 段**须满足 §C.4 的来源标签前置规则**——即 pack 中标记为 P0 的维度，其对应的需求条目必须在 `hiring_briefs` 中带来源标签。**导入校验新增一项**：若 pack 声明的 P0 维度无对应已溯源需求，导入**警告但不拒绝**（兼容 M1 无 RQ 层的既有 pack），界面提示"建议补齐需求溯源"。

> 为什么"内联内容"而非"引用文件"：pack 的价值在于**跨环境迁移**；若只存引用路径，导入到没有对应版本文件的环境会失败——这会直接摧毁"标准可迁移"的定位。

## E. 能力结构视图与待验证清单生成规则（v0.9.3 新增，对应 PRD EV-009/EV-010）

### E.1 三区块判定规则

| 区块 | 判定 | 说明 |
|------|------|------|
| 优势区 | 维度或技能簇档位 ≥B4 **且证据充分** | B5 展示为"显著超出"、B4 展示为"达标"；附支撑要点（如"2 个对口核心项目 + 量化成果"） |
| 短板区 | 档位 ≤B3 **且证据充分** | 须给出差距级别（如"要求 L4，证据 L2，差 2 级"）；**证据不足不得进此区** |
| 证据不足区 | 档位 = `insufficient` 或技能 = L0 | **不显示任何档位或分数**；自动生成待验证条目；排序键中标注"未参与比较" |

### E.2 结构摘要句模板（自动生成，须含三要素）

```
简历显示【优势：{≥B4 的维度/技能簇，含量化支撑}】，
【短板：{≤B3 且证据充分的项，含差距级别}】，
【证据不足：{insufficient/L0 项}】。
面试可进一步了解：{待验证清单 Top2-3}。
```

> **措辞纪律（v0.9.5 新增）**：摘要句是**系统口吻**，因此①不得出现"具备/掌握/精通/确实/证实"等能力断言（描述优势写"简历显示…较完整""有 N 条相关描述"）；②不得出现"真实性存疑/疑似夸大"等判断性措辞——系统不判断真实性。L4 的锚点名"精通"引用时必须写"简历自评精通"。

示例：见 `docs/recruit/09-能力画像样例.md`。

### E.3 待验证清单生成规则（两类触发）

| 类型 | 触发条件 | 条目模板（**中性陈述 + 面试可了解角度**） |
|------|---------|---------|
| 简历自评高于描述 | 自评等级 > 证据支持等级 | "{技能}：简历自评{等级}；现有描述为{场景}。面试可了解{方向}" |
| 关键项缺失 | 硬性要求技能为 L0，或核心维度 `insufficient` | "{项}：简历中未见相关描述。面试可了解{方向}" |

**无缺口时不生成条目**（返回"无待验证项，建议常规面试"），禁止硬造问题。EV-010（要问什么）与 EV-008（怎么问）共用本规则产出的缺口数据。

> **呈现边界（v0.9.5 新增）**：本清单**仅出现在报告的面试准备区**（服务于面试官备面，属面试官本来就要做的动作）；**不得**出现在首屏结构视图、档位表、排序页等主视觉位置，**不得**向人才端展示，**不得**以徽标/标签形式对候选人的证据可核验性作差异化标记。条目一律为**事实陈述**，**禁止"真实性存疑""疑似夸大""建议核实真伪"**等措辞——是否深究、是否察觉存疑，判断余地留给企业与求职者（见 PRD §6.3 结论表述纪律）。
