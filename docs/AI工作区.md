入口：求职者侧栏「AI 工作区」、工作台「进入 AI 工作区」以及「我的简历」中的「与 AI 完善」。页面地址 `/ai-workspace`。管理端和未经企业认证的招聘空间权限不受此功能改变。

## 使用过程

1. 选择自己的简历及可选的岗位，也可粘贴目标岗位描述（仅作为个人参照，不会发布招聘信息），新建一个材料固定的任务。只检查简历时不必选择岗位。
2. 点击「分析材料」或自由输入问题。结果展示观察、原文依据、具体下一步和可跳过的追问。
3. 回答追问后，点击本人消息旁的「作为经历补充保存」并确认；也可直接点击「补充经历」。这些内容单独标记为本人补充、未外部核验，保存后旧分析失效，需点击「更新分析」。普通对话不会自动成为经历证据。
4. 点击「生成优化草稿」或在聊天中提出优化需求，查看修改前后高亮，可逐段选择采纳及手动调整。确认后保存为新版本，并在当前工作区使用优化版；原始简历和文件保留。只添加草稿中确认的补充段落，不把整段对话直接写进简历。
5. 点击「找岗位并对照」查询平台可见岗位并发起后台契合度分析；结果中的「针对岗位优化」创建对应岗位任务。换材料时旧分析会失效，历史消息按材料版本隔离。历史任务按账号保存，可继续或删除，删除任务不会删除简历及已经保存的新版本。

桌面为材料 / 对话 / 结果三栏，可收起左右面板；窄屏切换对话、材料、结果视图。正常窗口高度下，材料、对话和结果各自滚动，输入区保持可见；推荐问题随对话滚动。初始材料选择表单可完整滚动，支持鼠标和键盘操作。窗口高度不超过 620px 时允许整页滚动，避免挤压工作区。

## 模型配置

工作区顶部提供模型选择，切换仅影响当前任务的后续请求。完整配置见 [模型选择与切换](模型选择与切换.md)。

后端根目录 `.env`：

```dotenv
LLM_MODE=deepseek
DEEPSEEK_API_KEY=服务器私密配置
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
COST_BUDGET_CNY=50
```

2026-10-13 按用户要求核对 V4.1 Flash：[官方发布说明](https://api-docs.deepseek.com/news/news260910/)对应的 API 模型名仍为 `deepseek-flash`。当前配置已经调用该模型，无须改为不存在于可用模型列表的 `deepseek-v4.1-flash`。使用现有服务器密钥的 `/models` 查询和最小文本调用均返回 HTTP 200。

2026-10-12 按用户授权从 AI 漫剧的后端环境文件复制 DeepSeek 密钥。官方 `/models` 验证可用模型为 `deepseek-flash`、`deepseek-v4-pro`，来源文件的旧名称 `deepseek-v4-flash` 已替换为可用的 `deepseek-flash`。原环境文件备份在 Git 忽略的 `data/backups/before-deepseek-workspace-*` 中。密钥不写入前端、文档或日志。变更环境文件后重启后端。

按 [DeepSeek JSON 输出文档](https://api-docs.deepseek.com/guides/json_mode/)使用 JSON 返回并设定输出上限，按 [Thinking Mode 文档](https://api-docs.deepseek.com/guides/thinking_mode/)对新模型显式关闭默认思考模式以控制协作请求等待时间。成本日志使用服务器配置的 token 单价估算，不等于提供商实际账单，部署前应核对单价。

模型未配置、处于 demo 模式时，页面明确提示 AI 未启用。材料选择与本人补充可用，但不会伪造 AI 对话或静默使用规则冒充模型。

## 授权和证据边界

这是受限的材料协作流程：后端选择授权材料，模型返回受约束的结构，后端校验后保存分析或待确认草稿。没有无限自主循环、任意函数执行或通用数据库工具。

- AI API 必须使用普通用户会话，且当前工作空间为 candidate。管理 cookie 或 `X-Session-Scope: admin` 被拒绝。真实身份从已验证会话获取，输入不允许 actor、role、SQL 或额外工具参数。
- `ai_sessions` 按环境和 actor 隔离；每次读取、写入、引用与确认重新检查归属。只有本人简历、本人已确认补充，以及当前允许查看的岗位可以成为来源。公开岗位在模型请求结束后再次验证可见性；账号停用、会话注销、空间变化或材料维护会阻止提交结果。
- 模型不接收账户 ID、owner、文件路径、密钥或管理资料。联系方式和敏感属性在输入时剥离。当前选定的可用材料会发送给所选模型的服务；前端提示提供商，中转模型额外提示请求经由外部中转。
- 历史对话、用户消息和所有文档作为不可信输入。Vue 以普通文本呈现，不执行 HTML、Markdown 图片或脚本。材料助手的工具调用仅由后端按白名单、当前材料权限及参数校验后执行。
- 引用必须来自本次来源，并且逐字为其子串。已有支持 / 部分支持必须引用求职者自己的材料，不能用岗位要求证明经历。补充来源标签由服务器决定。
- 草稿仅可改写可唯一定位的完整段落。服务器检查引用无法支持的新增数字、非法来源、重复段落、版本和状态；事实含义还需本人核对，不承诺程序能验证所有语义。本人在确认页面直接编辑的内容视为明确提供的自述，可补充新事实，但保存后标记为本人补充、未外部核验；它不冒充模型已验证的事实。确认才能写入新简历；重复确认返回同一版本。
- 补充后旧草稿失效。原简历保持不变，新简历记录 parent_resume_id、任务 ID、草稿 ID 及逐段修改依据；融入本人补充的段落在后续任务中仍保留“未外部核验”标签。新版本创建、来源记录、草稿状态和审计原子提交。
- 材料表达建议不生成能力等级、分数或候选人排名。第二阶段可调用原有岗位契合度服务，展示当前求职者与不同岗位的五档关系及顺序；档位沿用原确定性规则与校准状态，不由对话模型自行评分。

## 边界与配额

每个账号最多 100 个任务，每任务最多 60 条消息（通常 30 轮），十分钟最多发起 12 轮 AI 请求，账号同时只允许一个材料协作请求。预留状态持久化在 SQLite，跨进程有效，过期请求可恢复，版本冲突拒绝。普通单次流程每轮最多两次模型请求、单次传输超时 60 秒、返回上限 4500 token；材料 Agent 每轮最多 6 次模型调用、8 次工具调用，总预算 120 秒，单次 HTTP 上限 40 秒。模型失败不写入不合格结果，不覆盖简历。

对话上下文含最近 8 条历史消息（每条最多 1000 字）；重新分析和草稿生成不携带旧对话，仅使用当前确认材料，避免旧助手表述影响材料状态。上下文包含当前简历最多 18000 字、岗位最多 6000 字及最多 12000 字本人补充。以完整段落截取，长材料明确显示部分覆盖提示，不宣称全文分析。单条输入和补充最多 4000 字。历史全文在任务内保存，可以回看，但不是无限模型记忆。

## 数据与运维

添加 `ai_sessions` 表，不迁移或重写旧业务记录。变更前使用 SQLite backup API 备份业务和登录数据库到 `data/backups/before-ai-workspace-*`。系统合成数据清理顺序已包括 AI 任务，避免简历外键约束失败。真实数据引用合成数据时，原有清理保护继续生效。

自动测试使用独立临时数据库、假短信和假模型。`tests/serve_ai_preview.py` 是手动浏览器验收服务，使用 `artifacts/ai-browser-qa` 中的合成资料及配置的模型，不创建真实数据库中的测试账号，不发送真实短信。不要用于公开部署。

## 资料修改与对话历史（2026-10-13）

材料卡片的“修改”旁增加提示：资料修改会影响对话分析，建议重新分析全部资料。保存只暂存新的资料版本，停留在原对话；待更新提示持久化在当前账号的任务中，刷新和回看历史后仍保留。连续修改简历和岗位使用最新待更新资料，避免第二次修改覆盖第一次修改。

- “在新对话中聊天”：使用修改后的资料开启独立对话，带入已经确认的本人补充和当前模型；原对话的材料、消息与分析保留。
- “更新资料分析”：保持当前对话 ID 与完整消息，替换材料引用，归档旧分析与草稿，重新发起材料分析。旧消息标记为“修改前资料”，不会混入新资料的模型对话上下文。分析失败时保留更新后的资料，支持重新点击“分析材料”；原材料及旧结果的归档不会被覆写。
- 选择前，继续对话、生成草稿和补充确认由前后端共同阻止；资料可继续修改。版本校验、账号归属校验、事务回滚及重复请求保护继续有效。
- 顶部和材料区提供“对话历史”入口，显示标题、最近话题、更新时间与消息数，可搜索并打开完整对话继续使用。未选择的暂存版本不会占据对话列表。历史仅查询当前环境和账号，最多 100 个对话；连同内部暂存版本最多 400 条记录，删除原对话时清理其未启用的暂存记录，但保留已保存的简历版本。
- 长材料继续遵循现有段落截取上限并明确提示部分覆盖。重新分析会同时使用当前简历、岗位和已确认的本人补充，不表示取消原有上下文长度限制。
