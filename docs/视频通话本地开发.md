# 视频通话：本地版本

入口在消息中心的会话标题右侧。双方已接受沟通且岗位、企业与账号仍有效时，可以相互发起一对一视频通话。

## 使用流程

1. 运行现有本地启动方式，访问 `http://127.0.0.1:8501`（使用 8502 的开发环境也可以）。双方必须访问同一个地址和端口。
2. 在两个普通标签页分别登录招聘方与求职者账号。标签页会话已独立绑定，刷新或退出一方不会切换另一方账号，无需无痕窗口。
3. 在已接受邀请的会话中，点击“视频通话”。准备界面不会访问设备；点击“开启设备并呼叫”后才请求摄像头和麦克风权限。
4. 对方可在工作空间任意页面收到邀请。只有点击“接听视频”才会请求设备权限；婉拒不会启用设备。
5. 通话中可以静音、关闭摄像头、最小化窗口，或查看沟通资料并切换工作空间页面。切换页面保留通话；刷新、关闭网页、退出或切换账号会结束本机通话并关闭设备。
6. 挂断、婉拒、取消与未接听的记录显示在消息中心，保留方向、时间与已连接时长，不保存录音或录像。

同一账号的其他标签页可以看到“通话正在另一个窗口进行”，但不能获取连接信号、重复接听或接管设备。邀请超过 45 秒未接听自动结束；控制窗口失去心跳超过 40 秒后，在下一次服务查询时清理通话。短暂信号请求失败会保留待发送信号，以同一请求编号重试。

## 本地范围

- 使用浏览器原生 WebRTC，应用 API 仅传递双方连接信号，音视频不经过应用后端，不接入收费会议服务。
- 当前 `iceServers` 为空，已验证同一电脑、同一浏览器 Cookie 容器中的两个普通标签页以不同账号互传画面。尚未配置公网 STUN/TURN，不保证跨网络连通；这次没有部署服务器。
- 本机 `127.0.0.1` 和 `localhost` 可通过 HTTP 测试摄像头。公网 IP 的 HTTP 不支持浏览器摄像头功能；之后上线视频通话仍需 HTTPS，以及跨网络连接方案。
- 移动端已检查 390 × 844 视口布局；这不等于在实体手机、移动网络或 Safari 上完成通话验证。
- 自动化使用浏览器虚拟摄像头/麦克风，实际运行 WebRTC 与视频解码；尚未替用户启用实体摄像头、麦克风或听测扬声器。实体设备测试时，同室两端建议佩戴耳机，避免回声。

## 自动化验证

后端权限与消息流程回归：

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_video_calls.py tests/test_message_center.py tests/test_hiring.py -q
```

前端单元测试与构建：

```powershell
cd frontend
npm test
npm run build
```

浏览器集成测试使用独立合成数据库，不操作用户账号或现有投递：

1. 从项目目录运行 `tests/serve_video_preview.py`，等待 `http://127.0.0.1:8025/health` 返回成功。
2. 新开终端，在 `frontend` 目录设置 `$env:VITE_API_PROXY_TARGET='http://127.0.0.1:8025'`，运行 `npm run dev -- --host 127.0.0.1 --port 8515`。
3. 从项目目录运行 `tests/browser_video_calls.py`。可通过 `VIDEO_QA_BROWSER` 指定已安装的 Chromium/Edge 可执行文件，通过 `VIDEO_QA_URL` 更换前端地址。脚本默认使用当前开发机已安装的 Playwright Chromium。
4. 输出在 `artifacts/video-call-qa/`：验证 JSON、桌面/手机视口截图及独立数据库。测试完成可停止两个专用测试服务。

浏览器测试包括双向呼叫、实际远端视频解码、设备权限拒绝、取消后迟到的设备授权、静音与关闭摄像头、最小化跨页、信号网络中断恢复、移动端控件、取消/婉拒、多标签页接听隔离，以及关闭页面后释放双方设备。成功路径不模拟 API 或 RTCPeerConnection。

2026-10-19 本地验证：前端 104 项单元测试通过、生产构建通过；后端通话、消息中心与投递流程合计 28 项测试通过。浏览器完整流程通过，无页面脚本错误；两端实际收到并解码远端视频（采样尺寸 640×360、320×180）。桌面 1440×960、手机视口 390×844 截图已检查。

## 实现位置

- `app/video_calls.py`：通话状态、事务仲裁、权限、信号大小限制、过期清理和安全的历史数据。
- `app/main.py`、`app/db.py`：沿用现有用户身份、会话范围和 CSRF 保护，新增通话接口与独立数据表；不修改投递版本号。
- `frontend/src/video-calls.ts`：WebRTC、信号重试、设备与页面生命周期。
- `frontend/src/components/VideoCallPanel.vue`：全局来电、视频界面与最小化浮窗。
- `frontend/src/components/VideoCallHistory.vue`：会话中的通话记录。

SDP/ICE 只向双方控制窗口返回，有数量和长度限制，通话结束时删除。日志与历史接口不返回 SDP、ICE、内部账号编号或窗口控制编号。
