# 实现口径与资料对应

PRD 本体、完整上游 docs/06 与 docs/07 现已提供并全文核对，位于 docs/upstream/。本次量规以 PRD 结构版本 v2.3.2、定级功能设计与 Rubric v0.9.6 为权威来源；JSON 配置由上游 Markdown 表格转成可独立读取的数据资产。04 号 SRS、13 号方向选型和 02 号 UI 继续作既有流程依据。原始十五份资料未改动。

## 明确的实现取舍

1. PM 为产品中心，首次进入就是智能双选；企业与求职者共用确定性引擎、偏好维度与不可变填报快照。当前实现覆盖首期链路，并提供后续模块的基础页面和可执行接口。
2. 保留 FastAPI + Streamlit。名称「同频」作为界面品牌，系统名仍为「人才发掘 Agent 系统」。主紫色 #534AB7，改为冷浅灰背景和白色工作面；用双方原文对照作为视觉重点。
3. 上游 07 §A.4 为技能换档依据：L-R 为 +1/0/-1/-2/-3 时，依次 B5/B4/B3/B2/B1。原 08 号示例中 L2 对 R4 写为 B3 的地方视为笔误，实际为 B2。L0 不入档；技能名明确出现但无使用场景为 L1，仅自评为 L0。
4. 偏好同档代表「相符」，不代表「高于要求」。技术方向没有高低关系。企业侧四态映射为「偏好相符 / 偏好存在差异 / 偏好差异较大 / 无法判断」，能力层仍为相对岗位要求的高于/相符/低于关系。这样避免对称偏好被误写成有方向的能力差距。
5. 整体偏好先看三项必填：任一无法判断则整体无法判断；否则有低则低、有中则中、全高则高。选填单独列出，不参与整体。规则有明确版本，不做权重计算。
6. 缺失填报的引用显示固定的「未填报」状态文案，而非伪造原文；只有实际有填报依据时才出明确关系。整体缺依据不猜测。
7. 双方明确同意偏好用于对照后，该次匹配的另一方可见两份偏好引用。原始简历与企业内部报告仍按 owner 隔离；其他候选人的原文不开放。此处优先采纳「结果可展开到双方原文」这一核心契约。
8. 填报每次保存新增记录，旧记录不可变。画像每次确认版本递增；能力报告保存画像、判据和优先级快照。新版本不会覆盖历史报告。
9. 排序使用固定字典序。区间取较保守一侧，缺失维度使用内部缺失标记，不显示为 B1。已打回或更新的未确认报告不会继续沿用旧确认报告参与排序；完全同键则并列。
10. D2 按上游数值分界 90/75/60/40 落档；排名优先，采用 (1−排名/总人数)×100。GPA/满分只是比例，不是统计百分位，保留明确说明；不明满分按 5.0 保守计算并记录换算待确认，该逐项提示不进入主视觉表格。奖学金/荣誉只在已有成绩依据上最多上调一档，不单独成档。专业映射现在包含上游完整八领域，而非一份笼统相关专业列表。
11. 「系统不设合格线」是资料强制要求的否定性说明，必须作为完整语句允许；不能用逐字黑名单把本来要求展示的提示全部拦截。禁词配置集中在 presentation.json，扫描器允许这一个固定否定语句。
12. 配置资产不直接修改镜像文件，通过 data/config 中的原子文件修订或标准包 manifest 持久化；保留初始只读默认配置，解决原部署只读挂载与 PUT 保存接口的矛盾。

## 尚不能宣称完成的实测项

- 上游量规完整，但独立人工标注校准结果仍未提供。按用户确认，配置版本为 rubric-v0.9.6-aligned.1，状态为「上游已对齐、未冻结」；不伪造 20 对标注、校准一致率或冻结时间。首次交付时的草案报告保留原配置快照，不回写历史。
- 默认规则演示模式不是大模型。DeepSeek 实现已接入，可在 .env 切换；没有密钥时不会伪装模型输出。初筛与问答模板目前使用确定性规则，面试追问为基于缺口的模板，不宣称模型生成。
- 不内置伪造评测成绩。模型一致性、75% 初筛一致率、baseline +15pp 与熟练度准确率须用人工标注集实测。
- 向量检索为可选的真实 Chroma + BGE 集成，需要安装扩展依赖和模型权重；未装载时默认禁用。主流程不依赖联网下载。
- 当前演示身份头实现视角与 owner 过滤，但不是身份认证。生产写入明确禁用；不能把 demo 原型直接作为真实招聘系统上线。
- 外部 ATS、24365、工商接口按文档规划后置，本版本不联网抓取岗位或企业数据。

## 本次增量对齐与明确裁定（2026-10-11）

- D1/D2/D3/D5 五档锚点和证据要求逐档照录；原始「同上」与展开后的独立证据要求同时保留。insufficient 取通用纪律和相应特殊处理，不伪造上游不存在的独立锚点表。D4 上游没有另一张维度五档表，因此保留 L-R 映射原文与下中位数规则，不编造百分比命中锚点。L0–L4 与六条换档关系均可独立读取。
- D2 括号里的排名范围与数值百分位部分不一致，例如前 50% 与阈值 60；按明确数值阈值执行。B5 原文提到国家级奖学金，但本节前置规则明确最多上调一档、不单独成档，因此以该限制约束所有奖学金。D3 B4 的「无论文数字」照录，不擅自修正文档文字。
- JD 技能名没有等级词或任务场景时为 R1；每项技能使用其对应的原文词，不套用同句另一技能的熟练度。自评仅记录，不支持行为等级；有实际任务、对象和完成产出才命中 L2/L3/L4。输出包含命中特征和对应原文，L4 不通过孤立「架构/性能优化/论文」关键词猜测。真实模型的等级也必须通过证据校验；未识别到必要特征时保守返回不足或转人工，不声称规则覆盖所有自然语言表述。
- 通用纪律第 3 条与 A.4 的「不以自述定级」并读：原文熟练度不得被自由推断抬高；仅自评按 L0 处理，明确行为按行为锚点处理，自评高于行为描述只记入面试准备。未把自评作为高等级证据。
- D4 仅使用硬性技能的序数下中位数，加分项不参与。按用户确认，部分未知技能只用于推导可能的下中位数范围：结合各技能要求 R，枚举证据 L1–L4 可得到的合法关系；未知仍保留 L0/insufficient，不被指派最低档。全部未知为 insufficient。区间端点相同则保留相同端点并说明部分证据不足。D4 可跨多个档，是 A.4 明确规定的例外；模型的 D1/D3/D5 跨档仍只允许相邻档且须附依据。部分证据不足的 D4 放在证据不足结构区，避免把缺证据当短板。
- 按用户确认，只有明确「无相关项目/无实习经历」且教育和技能等基本描述存在时，才用事实 B1；仅未写或信息不完整一直为 insufficient。实习缺时长不猜月数；超过六个月但无核心或边缘职责描述，未命中任何完整锚点时保守不足。专业未覆盖、岗位主领域不唯一、项目缺必要角色/成果时同样保守不足，不能把规则未覆盖当低能力。
- 按用户确认，红线 8 的竞争排名禁令作用于求职者披露；保留 EV-005 要求的企业侧已确认报告比较。红线 14 的原文禁词存在内部维护例外：配置编辑器和标准包属于作者维护资产，允许保留量规原文；正常业务结果、理由与名单导出严格采用禁词配置。没有新增认证体系，内部编辑器仍是 demo 维护工具。
- 两端首屏与页脚各自包含「可能存在偏差」与「系统不设合格线」，默认可见。报告签发校验提示，企业理由只在渲染时映射 B 符号，原记录和双方 match_id 保持同源。禁词消费方读取同一配置，只允许固定否定句「系统不设合格线」；原文命中呈现禁词时阻断，不篡改原文来绕过检查。
- 对照表在 alignment-report.md，仅三张表；每一档、每条纪律、每条红线分别列出。验证记录在 verification.md。

## 必要改动范围说明

保留 FastAPI/Streamlit/SQLite、现有页面、表结构、访问隔离与审核流程，未改 app/main.py、app/db.py、app/models.py 或根目录十五份文档。除允许的确定性规则、配置、测试与说明外，以下配线/校验必须同步，否则新量规无法通过现有链路生效：

- app/agents.py 的定级 prompt/schema 与对应校验补充 anchor_hits/cross_band_reason；演示分支仅把旧草案判定替换为调用 deterministic 的新判据，不另起 Agent 架构。
- app/service.py 原本在此处写死 D4 汇总且丢弃区间，因此接入新的确定性结果，保留元信息和快照；人工改档同步理由，报告与导出补呈现校验。
- app/configuration.py 需接受并校验完整五维锚点和证据要求，同时拒绝不完整提示配置；app/security.py 需补上原先遗漏的政治面貌与院校层次信号。
- web/components.py / web/pages.py 需映射内部理由、显示区间依据、保留原文标签并更新旧草案说明，否则企业端会漏出 B 符号或继续声称资料未提供。未增删业务页面。

本轮进度说明已解释这些必要配线与校验的原因。新增字段限于上游示例已有的 cross_band_reason，以及本次提示词明确要求的锚点特征/引用与配置资产元信息。规则与 prompt 元信息分别更新为 local-demo-rules-1.1 与 evidence-rubric-v0.9.6-1。
