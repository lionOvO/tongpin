# 招聘 Agent 第三阶段

实施日期：2026-10-28。承接求职者材料助手和第二阶段流式协作，为招聘方接入独立、受限的材料 Agent。它帮助理解当前一份授权投递，整理经历、讨论技术与业务关联、准备有原文依据的面试追问。

## 使用流程

1. 已认证招聘账号进入「招聘 AI 工作区」，选择仍有效的授权投递。
2. 输入区默认启用「材料助手」。点击「整理简历精华」「技术与业务关联」「准备面试追问」，也可以自由提问。企业业务背景可先填写或保存。
3. 助手按问题选择工具。回答逐步显示，可展开执行步骤查看实际读过或检索过的材料；生成期间可点击「停止」。
4. 追问准备完成后，点击「查看建议并整理提纲」，在结果区选择「加入提纲」，调整顺序和备注，再点击「保存提纲」。工具准备建议时不会自动保存提纲。
5. 已保存对话、引文、提纲、历史归档、导出、资料卡与技术图谱继续使用原有流程。取消勾选「材料助手」可使用原普通对话接口。

打开页面、切换候选人和轮询进度均不会自动调用模型。招聘方始终使用 DeepSeek 官方配置，不继承求职者的中转模型选择。

## 工具与材料边界

| 工具 | 实际行为 |
|---|---|
| `read_application` | 读取当前投递中脱敏后的授权简历快照 |
| `read_job_requirements` | 读取投递时的岗位要求快照 |
| `read_business_context` | 读取招聘方本轮提供的业务背景，不能作为候选人事实 |
| `find_application_evidence` | 在当前授权简历快照中按文字定位，最多返回十二段 |
| `prepare_interview_outline` | 选择本轮已读取的简历引文，准备追问依据，最多四条；不写入提纲 |

工具没有任意简历、投递或账号编号参数。模型看不到未调用工具的完整来源；每条最终引用必须出现在本轮工具实际返回的对应来源中，再通过既有逐字引用校验。面试问题必须先准备提纲依据；保存提纲时，服务端再次校验每条问题确实来自当前对话已保存的回答。

不读取候选人后续私人简历版本、私人 AI 对话和其他企业材料。不修改候选人简历、不发送邀请或消息、不更改投递进度，也不提供候选人评分、排名或自动淘汰。检索未命中只表示当前文字未找到，不能视为能力不足。

## 执行、流式与停止

- `app/agent_runtime.py` 复用求职者与招聘者的 LangGraph 调度；每次调用的状态独立，不共享候选人记忆或工具结果。
- 每次最多六轮模型调用、八次工具调用，执行预算 120 秒，单次上游 HTTP 最多 40 秒。每轮检查费用预算，沿用企业账号每十分钟二十次、同时一份招聘对话的限制。
- 模型每轮以 `RecruiterMaterialAgent` 和独立提示版本记录调用及费用审计。
- POST `/applications/{id}/recruiter-assistant/turns/stream` 接受原对话字段及 `agent: true`，使用带 CSRF 和当前标签页身份的 SSE。事件为 `progress/reset/preview/done/error`。旧 `/turns` 保持兼容，`agent` 默认 false。
- 只展示最终 JSON 的 `reply` 内容增量，其他字段、工具参数和内部思考不进入预览。生成中的文字明确标为待校验，只有最终结构、引文及权限校验通过后才保存正式消息。
- GET 当前对话可恢复已持久化的执行进度和部分预览。刷新不会重发生成请求；前端先核对服务端记录，再允许重试。断开浏览器连接后已开始的服务端工作可以继续。
- POST `/applications/{id}/recruiter-assistant/cancel` 接受当前 `run_id`。停止会使执行令牌失效，后续工具、增量和正式回答不能提交。输入与已有对话、提纲保留。已发出的上游请求可能仍需等待响应或超时，已产生费用不能撤回。
- 每次工具、模型响应、预览、最终保存都重新检查当前身份、企业认证、投递归属、共享授权、材料指纹和会话版本。求职者撤回或流程结束时，同时清除执行状态及原有招聘私有对话。
- 复用有界 SSE 线程池和队列。服务重启不从中间 LangGraph 节点续跑；过期执行显示中断，可重新发送。历史归档不展示当前执行预览。
