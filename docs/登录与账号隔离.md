# 注册、密码登录与账号数据隔离

## 同一浏览器的多标签页登录（2026-10-19）

可以在两个普通标签页分别登录招聘方与求职者，无需无痕窗口。另开空白标签页首次访问时需要独立登录；刷新当前页保留该页账号，退出只撤销当前页所选会话。浏览器“复制标签页”可能复制 sessionStorage 并沿用同一会话，重新登录会生成新标识；测试不同账号时建议从新标签页打开登录地址。密码重设仍会撤销该账号所有会话，账号暂停和企业资格限制继续生效。

每个标签页、每个门户在 sessionStorage 保存一个随机 UUID 选择器，不保存密码、会话令牌或 CSRF 值。API、简历下载和视频通话离页请求都带上 X-Session-Tab；服务端仅使用对应命名的 HttpOnly Cookie，选中会话不存在时返回 401，不回退到最后登录的公共 Cookie。选择器本身不能作为身份凭据。工作空间切换用原会话认证并在新选择器下签发会话，避免改变复制窗口的身份；请求超时会分别核对目标及源会话，拒绝迟到响应。

验证：新增同 Cookie 容器多标签页测试 10 项通过；账号、密码、空间切换、管理权限及视频回归合计 71 项通过。前端 109 项测试与生产构建通过；真实浏览器验证两个普通标签页登录不同账号、分别刷新、退出隔离、新标签页独立登录以及双向 WebRTC 解码，无页面脚本错误。联调数据与现有业务库隔离。

旧 API 客户端不传选择器时仍使用原 Cookie 约定。网页升级到这版后，请刷新并在每个标签页重新登录一次；不会修改账号、密码、权限或业务材料。公网 HTTP 部署继续使用原来的 `_http` Cookie 前缀，HTTPS 的 Secure 属性按原配置保留。

## 使用

双击根目录的一键启动.bat，打开启动窗口输出的前端地址。首页右上角有「账号登录」和「注册账号」。新用户进入 `/register`，选择求职者或招聘方，通过 6 位短信验证码验证手机号，并设置及确认密码后注册。注册成功进入独立工作空间。之后在 `/login` 使用手机号和密码登录，也可切换验证码登录；验证码登录只登录已有账号，不会自动注册。账号的招聘与求职空间分别保存资料。求职空间可直接使用；招聘空间必须提交企业资质并经管理员人工核验，注册时选择招聘方也不能绕过审核。手机号在业务页面脱敏展示。退出后返回账号登录页。

之前快捷注册的账号及其材料均保留。尚未设置密码时，可以继续验证码登录，或从登录页「设置／找回密码」进入 `/forgot-password`，使用该账号原手机号验证后设置密码。已登录用户也可从工作空间右上角「设置密码／修改密码」进入。重设密码不会创建新账号或更换数据归属，会撤销该账号全部旧会话，并为本次验证签发新会话。

密码为 8–128 个字符，支持中文和空格，不会偷偷去除空格或截断。确认密码在前端核对；后端独立验证密码长度及非全空白。只存随机盐的 scrypt 哈希（N=32768、r=8、p=3），不保存明文密码、默认密码或固定验证码；参数参考 [OWASP 密码存储建议](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#scrypt)。密码核验与短信无关，已有密码的账号在短信暂不可用时仍可登录。未配置短信服务时，注册、验证码登录及重设密码会明确提示「短信服务待配置」。

## 配置短信

参考了餐小助的 `backend/src/services/sms-service.ts` 和 AI 漫剧的 `backend/src/sms.ts`，采用阿里云 **号码认证 PNVS**，接口为 `SendSmsVerifyCode` / `CheckSmsVerifyCode`。这与普通短信服务 Dysms 的 `SendSms` 是不同产品，签名与模板不能混用。

在同频项目根目录 `.env` 中填写：

```dotenv
ALIBABA_CLOUD_ACCESS_KEY_ID=填入有号码认证权限的 AccessKey ID
ALIBABA_CLOUD_ACCESS_KEY_SECRET=填入对应 Secret
ALIBABA_SMS_SIGN_NAME=号码认证控制台中的签名名称
ALIBABA_SMS_TEMPLATE_CODE=与该签名匹配的验证码模板 Code
ALIBABA_SMS_SCHEME_NAME=
ALIBABA_SMS_REGION=cn-hangzhou
AUTO_SEED=false
```

方案名留空时沿用阿里云默认方案，与餐小助和 AI 漫剧的现有实现相同，无需额外创建方案。如果改用控制台已有的独立登录方案，再填写对应名称；发送和核验必须使用相同方案。模板变量为 `${code}` 和 `${min}`，有效期 5 分钟。RAM 至少允许 `dypns:SendSmsVerifyCode`、`dypns:CheckSmsVerifyCode`，并开通短信认证服务、确认额度可用。

也兼容餐小助的 `ALIYUN_ACCESS_KEY_ID`、`ALIYUN_ACCESS_KEY_SECRET`、`ALIYUN_PNVS_SIGN_NAME`、`ALIYUN_PNVS_TEMPLATE_CODE`；上方变量优先。根据用户 2026-10-12 的明确要求，已将 `D:\餐小助\backend\.env` 的完整 PNVS 配置复制到同频根目录 `.env`，逐项核对一致，并沿用来源默认方案与区域；其他配置不变，原 `.env` 备份在忽略 Git 的 data/backups 目录。只在后端 `.env` 保存密钥，不使用 `VITE_*`，不把真实密钥提交 Git。后续更换配置后需重启服务。

发送使用官方动态验证码占位符 `##code##`；核验只接受远端 `Model.VerifyResult=PASS`。验证码不进入 API 返回值、日志或业务数据库。对超时不自动重发，防止重复扣费。

官方参考：[发送接口](https://help.aliyun.com/zh/pnvs/developer-reference/api-dypnsapi-2017-05-25-dir-sms-authentication-service/)、[核验接口](https://help.aliyun.com/zh/pnvs/developer-reference/api-dypnsapi-2017-05-25-checksmsverifycode)、[短信认证服务](https://help.aliyun.com/zh/pnvs/user-guide/sms-authentication-service)。

## 隔离范围

业务记录仍保存在 talent.sqlite3 的十五张表；auth.sqlite3 保存真实账号、密码哈希、会话哈希、验证码请求状态及限流计数。旧库启动时以增量方式增加密码、验证码用途、工作空间及企业认证结构，不改变原账号 ID、密码哈希、原始注册角色及业务 owner。旧招聘资料保留；无资质认证的旧招聘账号先进入求职空间，认证通过后恢复对应招聘资料。全部位于当前 DATA_DIR，随持久化数据卷保存。

- 身份由服务端会话绑定的账号 ID 和当前工作空间共同决定，企业认证状态由服务端独立核查。所有业务接口均要求认证，`X-Demo-Actor` 被忽略，未登录返回 401。
- 同角色的招聘账号之间，岗位、简历、批次、能力报告、审阅、偏好、记忆、审计与导出均按 owner 限制。猜中其他人的记录 ID 仍返回 404。
- 新建及迁移岗位默认为私有；确认画像不会自动公开。招聘方在岗位详情主动「公开岗位」后，求职者可读当前岗位描述与要求，但不能读内部历史版本、企业简历、报告或审计。
- 求职者的简历、私人粘贴 JD、岗位对照、个人偏好和自选岗位比较均属于本人。对公开岗位进行个人能力分析也不会把个人简历或报告发送给招聘方。
- 求职者在某个具体岗位上勾选共享并发起偏好对照，才向该岗位招聘方共享姓名与本次偏好依据。企业参与者列表仅来自自己岗位上已授权的对照；不遍历全平台个人偏好。其他岗位仍需单独授权。历史对照保留快照，岗位撤回公开不删除此前双方已共享的历史结果。
- 版本化判据是公共分析口径，可认证读取；修改全局配置、标准包、清理合成数据与装载示例仅允许管理员。普通业务接口对管理员仍按 owner 隔离；独立管理端提供显式的监管读取权限，可查看当前环境的岗位与简历原文，并为每次原文读取记录工作人员、对象和时间。列表仅显示摘要与脱敏手机号，不返回密码哈希、会话或原始手机号。
- 会话使用 HttpOnly、SameSite=Strict Cookie，有效期 12 小时，生产环境加 Secure；会话凭据不写 localStorage / sessionStorage。写操作检查 CSRF token 和请求来源。退出时服务端撤销会话，浏览器清空资料并拒绝旧请求回填；各标签页独立绑定自己的会话，普通登录和退出不会广播给其他标签页；管理端与用户端也分别隔离；会话失效时退出。
- 注册、登录与重设密码验证码按用途绑定，不可交叉使用；同一手机号共用发送冷却和总额限制。验证码 5 分钟过期、至少 60 秒重发间隔、最多 5 次核验；手机号按小时和每日限流，来源地址按发送及校验限流。密码登录按手机号每 10 分钟最多 10 次，按来源地址每 10 分钟最多 40 次；密码错误与未知账号使用相同错误，且执行同等密码哈希工作。状态持久化，重启不能绕过限流。反向代理后的来源地址当前按后端观察到的地址计数，多个用户可能共用限流桶；扩大部署需配置可信代理解析及短信服务侧总额限制。

生产 Cookie 要通过 HTTPS 使用。保持 Vue 与 API 同源代理；反向代理必须保留完整 Host（含端口）。默认本地启动仍使用 APP_ENV=demo，真实账号隔离在 dev/demo/prod 均生效，demo 指 AI 规则模式而不是身份认证。

## 管理员与旧材料

新注册账号不自动继承旧演示身份的数据；旧数据保留在原数据库，没有删除。如果要继续使用历史材料，先用自己的手机号验证码注册。停止前后端后，在项目根目录运行本机管理工具：

```powershell
# 将已验证注册的专门工作人员账号提升为平台管理员；执行后须重新登录
.\.venv\Scripts\python.exe scripts/manage_accounts.py promote-admin --phone 你的手机号

# 显式迁移原招聘演示身份的数据；先备份，保留记录 ID、原文、快照和引用
.\.venv\Scripts\python.exe scripts/manage_accounts.py claim-legacy --phone 你的手机号 --legacy-actor enterprise:demo
```

求职者历史身份可分别指定 candidate:lin、candidate:zhou、candidate:chen，目标必须是已验证账号的求职空间。工具只允许列出的旧演示身份，同侧迁移到对应工作空间，不混用两边 owner；招聘资料迁移不代表资质通过。备份在 data/backups。迁移后的岗位均设为私有，需要账号所有者重新公开。启用向量索引时重新写入该账号的 owner metadata。

无公共管理员注册或任意所有权迁移接口。管理能力由能访问服务器文件与数据库的本机维护者控制。原 Streamlit 页面作为源码参考归档，演示身份客户端不支持新认证，一键启动不再运行旧页面。

## 企业资质与招聘权限

首页招聘入口、登录时选择招聘方、工作台「企业认证 · 招聘方入口」均引导到 `/enterprise-verification`。必填企业全称、18 位统一社会信用代码、法定代表人、招聘联系人，并上传营业执照和招聘授权材料（PDF / PNG / JPG，每份不超过 5MB）。代码格式或文件类型校验不代表已核验真实性。提交后状态为「待人工核验」，不会自动放行。材料仅所属账号及平台工作人员可下载，附件以 attachment / no-store / nosniff 返回，不提供静态公开路径。

工作人员在 `/admin/enterprise-reviews` 下载材料，独立核对登记信息、营业执照和招聘授权关系，填写不少于 5 字的依据，再通过、退回或撤销。申请人无法自行审核，客户端也不能提交 admin、actor、account_id 来取得权限。退回后可重新提交；旧申请不能再次批准，审核事件保留。认证撤销会失效招聘会话，并立即停止岗位对求职者公开；资料与历史记录不会删除。

未认证的账号请求切换招聘空间返回 403；注册、验证码登录和密码登录选择招聘方只会得到求职身份及企业认证入口。只有认证通过后才能取得 enterprise owner，创建及公开职位。岗位公开读取还会核对所属企业的有效认证，撤销认证后即使原 published 字段仍为 true 也不公开。管理员是本机维护者显式授予的内部角色，没有公开的自助提权入口。

账号注册及密码只做一次；每个账号有两组独立 owner，旧侧 owner 原样保留。切换为当前标签页签发新会话及 CSRF 值，保留其他标签页原有会话，并清空当前页岗位、简历、报告、偏好及选择状态，拒绝旧空间迟到响应。只有已明确公开的职位及已主动共享的对照可跨空间读取。

上线前由同频平台安排专门工作人员。工作人员先用自己的手机号完成短信验证注册，再由服务器维护者在本机运行上述 `promote-admin` 命令，之后从 `/admin/login` 重新登录。内部人员没有注册角色限制；账号提升会撤销其全部旧会话，原工作空间的 owner 与资料不改变。此命令是维护者信任该工作人员的授权操作，不能交给普通用户执行。普通企业用户必须走材料申请和审核。当前没有接入工商登记自动核验服务或宣称材料自动验真，人工审核必须实际核查资料和授权。


## 独立平台管理端

入口：`/admin/login`，支持已授权工作人员密码 / 短信登录。管理端无自助注册、无身份切换按钮，普通招聘方和求职者都无法调用管理接口；知道 URL、伪造请求头或 role 也不能取得权限。未指定工作人员时不生成默认管理员或默认密码，企业申请保留待审核。

- `/admin`：当前环境的用户、待审核企业、岗位、简历及报告数量。
- `/admin/enterprise-reviews`：企业证明下载与审核。通过、退回、撤销均要求填写依据。
- `/admin/accounts`：手机号脱敏列表，可暂停 / 恢复普通账号。暂停立即撤销全部会话并禁止密码、短信登录，也停止其招聘岗位公开；恢复后须重新登录。工作人员账号不能由业务监管接口暂停。
- `/admin/jobs`：按空间标注招聘岗位与个人 JD。可查看原文，只有招聘空间的岗位可下架 / 解除限制。下架将 published 置为 false 并设限制，原招聘方修改画像也不能解除限制；解除限制后仍保持私有，须招聘方主动重新公开。
- `/admin/resumes`：分页简历摘要；工作人员主动打开原文时记录访问事件，普通业务权限及用户共享规则不变。
- `/admin/events`：资料读取、证明下载、资质审核及账号 / 岗位监管记录；包含工作人员 ID、对象、处理依据和时间。岗位处理还写入业务审计，企业审核保留原始审核历史。
- `/admin/governance`：版本标准包、配置维护与原有审计工具。

### 为未注册的工作人员预置管理账号

服务器维护者可在本机为明确指定的工作人员预置账号：

```powershell
.\.venv\Scripts\python.exe scripts/manage_accounts.py provision-admin --phone 工作人员手机号
```

这是仅限本机维护者的邀请方式，没有公开接口。新账号不设置默认密码，不签发会话，不自动发送短信。工作人员第一次在 `/admin/login` 选择验证码登录，以短信验证手机号；随后通过「设置／找回密码」再验证并自行设置密码。也可直接通过设置密码页面完成首次短信验证和密码设置，再进入管理端。

对已存在的手机号执行此操作会保留原账号 ID、密码、owner 与资料，赋予管理权限并撤销旧会话；重复执行不会覆盖密码或重新创建工作空间。暂停中的账号不会被此命令自动恢复。普通用户仍须通过验证码注册，管理员权限不能通过普通注册获取。


管理端登录跳转修复：`/admin/login` 对普通账号已有会话仍展示管理员登录表单，不再跳回 `/workspace`。普通账号访问 `/admin/*` 监管页面时先跳到管理登录页；登录成功后才进入管理端。管理端与业务端共用 8501 前端，但现已使用独立会话，分别登录账号不会改变另一端的身份。管理入口须使用完整路径 `http://127.0.0.1:8501/admin/login`，仅端口不会区分页面。前端 27 项测试、TypeScript 与生产构建通过；隔离浏览器验证已有求职者会话打开管理登录页、未授权监管跳转以及登录工作人员后进入管理概览。后端权限没有放宽。


### 同一浏览器同时使用管理端与用户端

分别打开 `/admin/login` 和 `/login?role=candidate`，可登录两个不同账号。管理端使用 `tongpin_admin_session_<页面标识>`，用户端使用 `tongpin_session_<页面标识>`，均为 HttpOnly / SameSite=Strict Cookie。服务端 sessions 新增 session_scope 并绑定实际签发的范围；仅改 Cookie 名、请求头或客户端 role 无法把普通令牌变成管理令牌。所有 `/admin/*`、`/auth/admin/*` 和企业审核请求强制使用管理会话，没有普通会话回退。

身份读取、退出和密码设置提供管理端专用接口；管理端密码页面为 `/admin/forgot-password`。共用的业务、配置与证明下载请求通过 `X-Session-Scope` 与 `X-Session-Tab` 选择对应 Cookie，服务端仍核对令牌的持久化范围和工作人员角色。普通工作人员账号从用户登录接口登录仅获得普通工作空间，不获得管理权限。管理会话不能切换求职或招聘身份。

前端按路由选择端，切换端时清空原端资料并中止请求，迟到响应不能回填。已移除全局登录 BroadcastChannel；同一端的不同标签页也不会同步切换账号。密码重设会撤销该手机号的所有会话（包含两端），账号暂停、授权撤销仍按原安全规则执行；不同手机号的会话不因密码重设被撤销。
