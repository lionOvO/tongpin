# 同频：前端重构与主要技术

## 本次结果

默认用户界面已由 Streamlit 改为独立 Vue 页面，保留双端全部原有业务入口。招聘端按「岗位与需求 → 简历与初筛 → 报告与审阅 → 已确认报告比较」推进；求职者端按「简历 → 偏好 → 具体岗位对照 → 自选岗位比较」组织。岗位采用列表与详情，技能采用双方原文分栏，报告提供常驻的审阅入口。小屏导航收为抽屉，表格在自身容器内横向滚动。

浅色底、紫蓝强调色、中文衬线标题与清晰正文保持同频原有气质。图标使用维护中的 @lucide/vue；不依赖远程字体或图片，不套用 Streamlit 控件。展示名称和原文由 Vue 的文本绑定转义，不使用 v-html。

## 技术各自做什么

| 层次 | 技术 | 项目中的用途 |
| --- | --- | --- |
| 页面 | Vue 3.5、Composition API | 把工作台、岗位、简历和报告拆成可复用组件，局部更新，不需要重新运行整个页面 |
| 类型 | TypeScript | 编译时检查接口、组件参数和状态使用，减少字段拼错、选项类型错误 |
| 构建 | Vite 8、Vue Router 4 | 快速本地调试与生产打包；为业务页提供独立路径与前进、后退导航 |
| 视觉 | 自定义 CSS、Lucide 图标 | 统一排版、颜色、分栏、响应式与键盘焦点，界面不依赖默认控件皮肤 |
| 接口 | Python 3.13、FastAPI、Uvicorn | 接收请求、执行业务、返回结果，提供 OpenAPI 接口文档 |
| 校验 | Pydantic 2 | 校验必填项、单份 JD 长度、枚举选项、技能等级与 AI 结构化输出 |
| 数据 | SQLite、WAL、外键与事务 | 保存现有本地数据、历史快照与审计；简历及候选人记录一起成功或一起回滚 |
| AI | HTTPX、可选 DeepSeek | 从文字整理结构化证据；默认仍使用明确标注的本地演示规则 |
| 可选检索 | BGE 模型与本地索引 | 检索相关简历上下文；未启用时不加载模型，启用后也不自动删除材料 |
| 部署 | Docker Compose、Nginx | Vue 打包成静态文件，通过同源 /api 代理访问 FastAPI；SPA 路由支持直接刷新 |

Vue 和 React 都能实现这种页面。本项目主要是双端工作流、表单与证据详情，Vue 的组件模板与渐进接入适合当前规模，也便于维护者衔接「灵境造物」项目。美术效果由布局和交互设计决定。FastAPI 与 Pydantic 是现代技术，已有业务规则和数据结构可直接复用，因此没有为换名字重写后端。

## 已处理的问题

- 生产环境原本仅禁止写入，演示身份仍能读数据。重构时关闭了这条入口；随后已接入真实手机号会话，全部环境要求认证，X-Demo-Actor 不再参与授权。
- 岗位标题中的技能名会抢占正文中的明确熟练要求。解析现在优先选择真实要求与技能对应的原文；补充了数据、测试、基础设施方向的规则识别。
- 简历原文写入失败时可能留下没有简历的候选人。现在候选人、简历和导入审计在同一事务内，失败回滚并清理本次生成的原文文件。
- 自选 JD 原本只限制列表数量。现在每份 JD 均限制为 20–30000 字符，文件导入每批最多 50 份、累计最多 50 MB，单份仍最多 10 MB。
- 退出或会话过期会立即清空账号材料与选择，迟到的旧响应不写入当前状态；不再允许页面切换演示身份。
- 确认报告后审阅菜单即时切换，已确认报告仍锁定；人工修改须保留理由，缺少原文不能改成明确关系。
- 批量能力分析在前端逐份调用并显示进度，成功结果逐份落库；自选多岗位分析保留相应等待时间，超时提示说明需刷新确认服务端是否已完成。
- 默认后端安装与容器只安装运行时依赖，Streamlit 和旧验证工具从新运行链路分离；原锁文件仍用于旧界面对照。
- 一键启动改为 Vue + FastAPI，保留端口自动避让、动态代理、健康等待、日志以及只停止本次启动进程的机制。

偏好版本不一致或过期的拦截、原文证据校验、D4 保守区间、企业结果禁词、求职者不见面试追问、两处偏差提示、人工确认后才比较等原有规则继续保留。量规仍为「上游已对齐、未冻结」，不宣称人工校准通过。

## 启动与验证

双击根目录的一键启动.bat。启动终端显示实际地址；默认前端从 8501、API 从 8000 起寻找可用端口。前端依赖由 package-lock.json 固定；后端运行依赖由 requirements-runtime-lock.txt 固定。更新依赖前须关闭正在运行的本项目 Vue 进程，Windows 会锁定原生构建模块。

```powershell
python start.py
cd frontend
npm run test
npm run build
cd ..
# 在项目根目录
.\.venv\Scripts\python.exe -m pytest -q
docker compose config --quiet
```

浏览器联调使用独立 DATA_DIR，不更改用户现有材料。已通过后端 112 项测试、前端 8 项测试、TypeScript 检查与生产构建；npm 全量依赖审计在本次扫描中报告 0 项已知漏洞。pip check 与 Docker Compose 配置校验通过。浏览器已验证招聘主流程、偏好保存与共享、求职者对照、自选 JD 比较、样本不足、内部自检及 390px 窄屏。Docker 引擎未运行，因此未执行容器镜像构建或正式部署。
