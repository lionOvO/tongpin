# 岗位契合度与推荐顺序

求职端侧栏 **岗位契合度**（`/compare`）提供统一入口。选择一份本人简历，勾选 1–20 个可访问的已确认岗位，或粘贴 2–20 个完整岗位描述。岗位详情也提供“分析岗位契合度”入口，自动预选该岗位。原单岗量规对照、AI 对话、偏好对照和岗位参考基准保留；招聘端的人工确认报告比较不变。

## 判断口径

`job-fit-known-evidence-v2` 只使用有可定位原文的现有技能与项目依据，不新增模型总分或匹配百分比。

| 档位 | 已有证据归纳的中位关系 |
| --- | --- |
| 很高契合 | B5 |
| 较高契合 | B4 |
| 一般契合 | B3 |
| 较低契合 | B2 |
| 很低契合 | B1 |

主要技能逐项参与，加上项目经验 D3；没有主要技能要求时使用其他列明技能。D4 与技能明细不重复计算。历史记录只有 D4 而无技能明细时，仅使用依据充分的 D4；旧“部分证据不足”区间不能代替真实已知技能。

只取有原文依据的条目，按既有关系取靠低的中位档，真实跨档使用较保守一端。缺失条目不记零、不视为能力低、不要求求职者补充；只在“未见相关描述”中提示。界面同时显示可用依据条目数与判断范围，避免把部分已知解释成所有要求均已确认。专业、学业及其他实践信息单独提示。

五档按从高到低排名，同档位并列。旧排序键包含未描述维度的零哨兵值，因此不再用于求职者契合度排名；缺失项数量不影响同档排名。完全无可判断的技术或项目依据时显示“暂无判断依据”，仅提示、不分配档位和位次，该状态不属于第六个契合档位。

已有历史在读取时使用原保存的 `dimensions` 与 `skill_levels` 重新归纳，不再次调用 AI，不改写原始历史或材料。返回 `display_policy_version` 与 `policy_updated` 说明展示规则变化；单岗报告也使用同一口径。缺少证据明细的早期记录不补造结论。招聘端报告量规与人工排序不变。

## 后台任务

- `POST /compare/tasks`：`resume_id`、`job_ids` 或 `job_texts`、`request_id`，返回 202。
- `GET /compare/tasks/{id}`：本人任务进度、已完成结果和逐岗位错误。
- `POST /compare/tasks/{id}/retry`：使用新的 `request_id`，只补跑失败或中断的岗位，合并已完成结果，原记录保留。简历或任一岗位版本变化时拒绝合并，要求重新完整分析。
- `GET /compare/runs`：最近 50 条本人历史，不返回后台输入快照和指纹。
- `POST /compare/rank`：保留原同步 API，与新任务共用判断口径。
- `POST /fit/analyze`：单岗报告也附带相同 `fit_summary`。

默认直连 DeepSeek。复用既有 `job_comparison_runs` 表，不迁移或重建数据。每个服务实例 2 个执行线程、最多 8 个排队或执行任务；生产继续使用 1 个 Uvicorn worker。同一请求编号防重复，处理中的同一简历和同一组资料复用任务，不同输入返回冲突。网络超时重试沿用请求编号；页面轮询后台任务，离开再返回能恢复进度。重启时标记中断并保留已完成结果，不自动重放模型调用。

提交时核对本人简历和全部岗位权限。每项开始前及模型返回后，重新检查岗位可见性、版本、内容指纹和简历内容；执行中账号停用也会停止任务。失效、撤回公开、改版或已删除资料不生成新结果。已完成历史保留当时依据，并提示资料修改后需重新分析。

- `tests/test_job_fit.py`：档位边界、缺失与区间、并列、权限/CSRF、预检、防重复、异步进度、部分失败、资料变更、中断恢复、兼容同步和单岗报告。

- `tests/browser_job_fit.py`：1920/1440/1024/768/390/360 宽度，交互、依据展开、刷新恢复、历史、减少动态效果；仅拦截合成请求。
- 相关认证、报告任务、量规对齐和系统测试回归，前端完整测试与生产构建。

模型输出质量仍需结合实际简历和岗位核对；本次验证不声称执行了真实 DeepSeek 调用。

## 2026-10-17 本地失败修复

实际日志显示 `INTERVAL_INVALID`：模型为单档返回了 `["B3"]`，重试时又可能产生缺少跨档说明的区间。现在明确提示单档使用空数组，并把与所选档位相同的单元素或重复端点数组统一成空数组；保留原始档位与引用。真正不合法的跨档、缺失跨档依据和无效引用仍拒绝签发。

页面标出失败岗位名称，提供“仅重试未完成岗位”，不会重复分析成功项。修复后在本机对原失败岗位执行了一次真实 DeepSeek 重试：任务由 5/6 补齐为 6/6，无错误，原 5 项结果完全保留。此验证不涉及服务器部署。

验证：后端 Agent 与契合度测试 31 项、启动测试 8 项，前端完整测试 97 项通过，生产构建通过；6 种浏览器宽度无横向溢出或脚本错误。Windows 隐藏后台进程不依赖控制台重载信号，由本地启动器监测 app 下 Python 文件并重启自有 API 进程树，已实际验证修改后服务恢复。
