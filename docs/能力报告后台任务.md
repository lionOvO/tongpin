# 能力报告后台任务

“简历与初筛 → 生成能力报告”通过短请求创建后台任务，不再让浏览器等待整个模型生成。任务及进度存入 SQLite，刷新或重新进入页面时查询恢复。默认使用 DeepSeek 官方，失败时不自动改用中转模型。

- `POST /assessment-tasks`：岗位 ID、简历 ID 列表、请求编号；立即返回 202 与任务。
- `GET /assessment-tasks?job_id=...`：当前招聘账号的岗位任务。
- `GET /assessment-tasks/{id}`：读取单个任务的进度、报告编号和失败原因。

同一请求编号重试返回原任务；同一简历已有进行中的任务时不重复生成。界面提交回执丢失后先查询进度，再重试仍复用编号。进行中的任务不会占用页面的全局操作锁。模型超时或证据校验失败会保留具体原因，零报告不会提示生成成功。

模型 HTTP 适配层现在同时限制整次请求耗时和响应体大小，防止服务持续返回保活空白而绕过读取超时。当前报告每次模型请求最多 90 秒，仍保留一次同模型重试；失败后任务返回明确原因，不切换供应商。Chat Completions、Responses 及 Responses SSE 均使用同一总时限。

任务仅对当前已认证招聘账号开放，提交、运行与保存时校验简历授权；结束共享后无法读取相关任务和报告。后台调用使用提交时的审计上下文，不持久化登录 Cookie 或 API 密钥。

当前部署为单 API 进程，最多两个报告任务同时运行，最多八个执行或等待中的任务。服务重启后将未完成任务标为中断，不自动重放付费调用；已经生成的报告保留，用户核对后可重新提交未完成材料。此实现不支持多个 API 进程共享任务队列，若扩容需替换为独立任务队列与工作进程。
