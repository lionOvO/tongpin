# 求职者 Agent 第二阶段与流式协作

实施日期：2026-10-28。承接[第一阶段材料 Agent](求职者材料Agent第一阶段.md)，本阶段在求职者 AI 工作区增加岗位查询、现有多岗位契合度后台任务，以及流式回答和可选择采纳的简历改写。招聘端 Agent 不在本次范围内。

## 使用方式

1. 在 AI 工作区选择自己的简历，使用 DeepSeek 官方模型并启用材料助手。
2. 输入“根据我的简历找相关岗位并分析契合度”，或点击“找岗位并对照”。助手查询当前有权查看的岗位，按需发起后台分析。
3. 工作区显示分析进度、五档契合度、推荐顺序、相符之处和现有差距。当前材料未说明的内容只作可跳过的提示，不要求补充，也不因为缺少证据降低档位。
4. 点击结果中的“针对岗位优化”，使用当前简历和该岗位创建独立任务并生成改写建议。也可以直接在原对话输入“优化这段项目描述”。
5. 点击“查看修改前后”，查看删除线及新增下划线，逐段勾选采纳范围；可手动调整建议。再次确认“采纳并使用优化版”后，才保存新简历并切换当前工作区的材料引用。

原始简历及原文件始终保留。新版本不会替换既往投递中的授权快照。未采纳段落保持原样，重复确认不会再创建一份简历。手动修改保留本人自述的来源标记。

## 岗位工具与已有业务的连接

| 工具 | 功能 | 范围 |
|---|---|---|
| `search_jobs` | 查询已确认、当前用户可见的岗位 | 每次最多 12 个；按查询文字匹配，不把命中当成契合度 |
| `start_comparison` | 发起现有五档契合度后台任务 | 每次 1—6 个查询结果引用；不允许模型传入任意简历或数据库 ID |
| `read_comparison` | 读取本工作区关联的任务与结果 | 不允许读取任意任务编号；已有结果可继续讨论 |

工具只查询平台内岗位，不访问外部招聘网站。发起分析时重新核对岗位可见性和版本；结果展示时也重新检查。失效岗位对应的旧结果被隐藏，剩余结果按原有规则重排。

分析直接复用 `ComparisonTasks`、`TalentService.evaluate` 和 `job_fit`，默认使用 DeepSeek 官方服务。档位和排序来自既有规则，不由对话模型自行编分或改写。一个 Agent 执行中重复调用发起工具只关联一个任务。

比较使用发起时已保存的简历快照。已确认但尚未融入简历的补充内容不参与这次多岗位比较，卡片中明确说明。采纳优化版或更换材料后清除当前工作区对旧比较的关联；原比较记录仍可在契合度页面回看。

## 流式回答

前端通过带当前标签页身份和 CSRF 的 POST `/ai/workspaces/{id}/turns/stream` 建立 SSE 连接。后端直接读取官方模型的内容增量，同时重组工具调用片段；不是先等待完整回答再模拟打字。

事件包括 `progress`、`reset`、`preview`、`done`、`error`。仅 `reply` 字段逐步呈现，工具参数、其他结构化字段和内部思考不进入预览。界面明确标注生成中的文字尚待校验。最终结构、原文引用和改写依据通过既有校验后，才保存正式消息、分析和草稿；不合格时清除预览并保留已有结果。

刷新页面通过 GET 读取持久化进度与预览，不自动重发 POST。网络断开后，服务端已经开始的工作可继续；用户可刷新查看。尚未结束的比较任务继续由原后台服务处理。停止材料助手会阻止后续工具和回答提交，但不会取消已发起的独立岗位比较任务，也不能撤回已产生的模型费用。

这不是 LangGraph 节点自动恢复：服务重启后不从中间工具节点续跑。比较任务沿用既有服务重启中断机制；材料助手的过期执行显示中断，用户可重新发送。

## 保存和权限

- 按当前环境、账号和求职者工作空间检查访问权限；不增加招聘方或管理员的可读范围。
- 工具白名单、严格参数校验、执行令牌、材料版本和会话状态检查继续生效。
- 每轮最多 6 次模型调用、8 次工具调用，执行预算 120 秒，单次模型 HTTP 上限 40 秒。沿用账号频率和费用预算检查。
- SSE 最多 4 个并行工作线程，事件队列有上限；慢连接断开后以数据库状态为准，不重放写入。
- 改写确认在同一事务中创建新简历、保存来源、更新草稿状态，并更新工作区 SQL 简历引用。前端默认切换到新版本，API 的 `continue_in_workspace` 默认 false 兼容旧调用。
- `indices` 指定采纳的段落；省略时兼容旧接口的全部采纳。手动编辑只允许作用于所选段落。未确认不写入简历。
